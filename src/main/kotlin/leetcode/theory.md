# Теория по определению сложности, выбору структуры данных и алгоритму

Выбор алгоритма и оценка сложности — ключевой навык для решения задач. Давай
разберём системный подход.

## Шаг 1. Внимательно прочитай задачу и выдели ограничения

Обычно в условии даны ограничения на размер входных данных (n, m). От них
отталкиваемся.

**Пример ограничений и допустимые сложности:**

| n (размер данных) | Примерная допустимая сложность |
|-------------------|--------------------------------|
| n ≤ 20            | O(2ⁿ), O(n!) — полный перебор  |
| n ≤ 100           | O(n³) — можно кубический       |
| n ≤ 1000          | O(n²) — квадратичный           |
| n ≤ 10⁵           | O(n log n) или O(n)            |
| n ≤ 10⁷           | O(n) или O(log n)              |
| n ≥ 10⁸           | O(log n) или O(1)              |

Эту таблицу полезно запомнить. Если видишь, что n = 10⁵, значит алгоритм O(n²) (
10¹⁰ операций) не пройдёт по времени.

## Шаг 2. Определи тип задачи

Задачи обычно относятся к нескольким «шаблонам» (паттернам). Распознав шаблон,
ты сразу сужаешь круг возможных алгоритмов.

- **Поиск элемента в массиве** → бинарный (если отсортирован) или хеш-таблица.
- **Сортировка** → встроенная `sort()` (O(n log n)).
- **Проверка наличия пары с суммой** → сортировка + два указателя или хеш-сет.
- **Пересечение/объединение интервалов** → сортировка по началу, жадный проход.
- **Кратчайший путь в графе** → BFS (не взвешенный), Дейкстра (взвешенный, нет
  отрицательных), Форд-Беллман (есть отрицательные).
- **Поиск компонент связности** → DFS / BFS / DSU (система непересекающихся
  множеств).
- **Задачи на подотрезки / подпоследовательности** → динамическое
  программирование (DP), два указателя, префиксные суммы.
- **Оптимизация (мин/макс)** → жадный алгоритм (если работает), DP, бинарный
  поиск по ответу.
- **Подсчёт чего-либо** → комбинаторика, математика.

## Шаг 3. Оцени минимально возможную сложность

Задай себе вопрос: «Сколько входных данных я обязан прочитать?» — это уже O(n)
или O(n*m). Часто лучший алгоритм не может быть быстрее, чем O(n).

**Примеры нижних границ:**

- Найти максимум — нужно посмотреть каждый элемент → O(n).
- Отсортировать — в общем случае нельзя быстрее O(n log n) (сравнениями).
- Найти пересечение двух массивов — O(n log n + m log m) или O(n+m) с
  хеш-таблицей.

## Шаг 4. Подумай о структурах данных, которые помогут

Kotlin (и Java) предоставляют богатую стандартную библиотеку. Часто выбор
правильной структуры данных уже даёт нужную сложность.

| Задача                             | Подходящая структура в Kotlin       |
|------------------------------------|-------------------------------------|
| Быстрая проверка наличия элемента  | `HashSet` (O(1) в среднем)          |
| Хранение пар ключ-значение         | `HashMap`                           |
| Подсчёт частот                     | `mutableMapOf` с инкрементом        |
| Очередь с приоритетом (мин/макс)   | `PriorityQueue`                     |
| Сортировка + удаление дубликатов   | `sortedSetOf()` или `toSortedSet()` |
| Работа с последовательными данными | `List`, `Array`                     |
| Стек / очередь                     | `ArrayDeque`                        |

## Шаг 5. Приведи пример рассуждения на конкретной задаче

**Задача:** «Дан массив целых чисел nums и число k. Найти количество пар (i, j),
i < j, таких что nums[i] + nums[j] == k». Ограничения: n ≤ 10⁵, значения до 10⁹.

Рассуждение:

1. n = 10⁵ → нужна сложность O(n log n) или O(n).
2. Простой перебор всех пар — O(n²) = 10¹⁰ — не подойдёт.
3. Используем хеш-таблицу: проходим массив один раз, для каждого элемента
   смотрим, сколько раз встречалось `k - nums[i]` раньше.
4. Сложность: O(n) по времени, O(n) по памяти.
5. Пишем код на Kotlin с `HashMap<Int, Int>`.

```kotlin
fun countPairs(nums: IntArray, k: Int): Int {
    val freq = mutableMapOf<Int, Int>()
    var count = 0
    for (num in nums) {
        count += freq[k - num] ?: 0
        freq[num] = (freq[num] ?: 0) + 1
    }
    return count
}
```

## Шаг 6. Не забывай про худший случай и амортизацию

При оценке сложности смотри на **наихудший случай** (big O). В Kotlin `HashMap`
в среднем O(1), но в редких случаях может быть O(n) (из-за коллизий). В
соревнованиях это обычно допустимо, но важно знать.

## Шаг 7. Проверь себя тестами и граничными случаями

Даже выбрав алгоритм, проверь:

- Пустой массив.
- Один элемент.
- Все элементы одинаковые.
- Максимальные входные данные (мысленно или бенчмарк).

Если время выполнения в голове кажется большим, попробуй улучшить.

```
Читаю задачу
↓
Смотрю ограничения (n, m, t)
↓
Понимаю, что нужно вычислить / оптимизировать
↓
Вспоминаю классические алгоритмы для такого типа
↓
Прикидываю их сложность — подходит ли?
↓
Если да — выбираю, если нет — ищу другой (часто с хешами, сортировкой, жадностью)
↓

```

## Главные советы по тренировке

1. **Решай задачи на LeetCode / Codeforces / Codewars** — там автоматически
   проверяется время.
2. **После решения читай разборы** — узнаешь, можно ли было быстрее.
3. **Запоминай шаблоны** (два указателя, скользящее окно, префиксные суммы,
   BFS/DFS, DP по подмаскам).
4. **Учись оценивать сложность чужого кода** — это прокачивает навык.
5. **Используй стандартные функции Kotlin** (`sort`, `binarySearch`, `groupBy`,
   `associate`, `fold`) — они уже оптимальны.

Со временем ты будешь видеть задачу и сразу понимать: «Здесь нужна сортировка +
два указателя, O(n log n)» или «Тут без динамики не обойтись, но n=50, значит O(
2ⁿ) пройдёт».

# Еще про сложность и алгоритмы

Отлично, ты подошёл к ключевому моменту — как в голове соединить **сложность**,
**структуру данных** и **алгоритм**. Это и есть инженерное мышление. Давай
разложим по полочкам.

## Что означают эти три понятия в связке

- **Сложность (Big O)** — это «сколько операций и памяти нужно». Она диктует,
  какой алгоритм и структура данных допустимы.
- **Структура данных** — это способ хранения и доступа к данным. Она определяет,
  какие операции быстрые (O(1), O(log n)), а какие медленные (O(n)).
- **Алгоритм** — это последовательность действий, которая использует структуры
  данных для решения задачи. Он выбирается исходя из требуемой сложности и
  доступных структур.

Связь простая: **ограничения задачи** → **нужная сложность** → **подходящая
структура данных** → **конкретный алгоритм**.

## Как структура данных диктует сложность операций

Вот базовые операции для популярных структур. Запомни эти цифры — они помогут
выбирать.

| Структура данных              | Доступ по индексу    | Поиск элемента         | Вставка / Удаление            |
|-------------------------------|----------------------|------------------------|-------------------------------|
| Массив (Array)                | O(1)                 | O(n)                   | O(n) (в середину)             |
| Список (ArrayList)            | O(1)                 | O(n)                   | O(1) в конец, O(n) в середину |
| Связный список (LinkedList)   | O(n)                 | O(n)                   | O(1) (если знаешь узел)       |
| Хеш-таблица (HashSet/HashMap) | —                    | O(1) средн.            | O(1) средн.                   |
| Дерево (TreeSet/TreeMap)      | —                    | O(log n)               | O(log n)                      |
| Куча (PriorityQueue)          | O(1) для min/max     | O(n) для произвольного | O(log n)                      |
| Стек / Очередь (ArrayDeque)   | O(1) доступ к концам | O(n)                   | O(1)                          |

## Примеры связки на LeetCode

### Задача 1: «Two Sum» (найти индексы двух чисел, дающих сумму target)

- Ограничения: n до 10⁴–10⁵. Простой перебор O(n²) может не пройти.
- Мы хотим O(n). Для этого нужно быстро проверять, было ли число
  `target - nums[i]` раньше.
- Какая структура даёт O(1) поиска? **Хеш-таблица**.
- Алгоритм: один проход, кладём в HashMap (значение → индекс), для каждого
  элемента ищем дополнение.
- **Связка**: ограничения → O(n) → HashMap → алгоритм с одним циклом.

### Задача 2: «Top K Frequent Elements» (найти k самых частых элементов)

- Нужно подсчитать частоты и извлечь k максимальных.
- Подсчёт частот — HashMap (O(n)).
- Извлечение k максимумов — можно отсортировать O(n log n), но лучше
  использовать **кучу** (PriorityQueue) размера k: O(n log k).
- **Связка**: частота → HashMap, выбор топ k → куча, алгоритм — подсчёт +
  приоритетная очередь.

### Задача 3: «Merge Intervals» (объединить пересекающиеся интервалы)

- Сначала нужно **отсортировать** интервалы по началу. Сортировка O(n log n) —
  это нормально для n ≤ 10⁵.
- После сортировки один проход O(n) с жадным слиянием.
- Какая структура? Просто список (List). Алгоритм — сортировка + линейный
  проход.
- **Связка**: без сортировки пришлось бы O(n²), сортировка + линейный = O(n log
  n).

### Задача 4: «Binary Search» (классика)

- Массив отсортирован. Нам нужен поиск за O(log n).
- Структура: массив с произвольным доступом (индексация O(1)).
- Алгоритм: бинарный поиск (деление отрезка пополам).
- **Связка**: массив + O(log n) → бинарный поиск.

## Как подходить к новой задаче (пошаговый план)

1. **Посмотри ограничения** (n, m, k). Прикинь, какую сложность они допускают (
   по таблице выше).
2. **Определи тип задачи** (поиск, оптимизация, подсчёт, работа с графами и
   т.д.).
3. **Вспомни стандартный алгоритм** для этого типа и его сложность.
4. **Выбери структуру данных**, которая даст нужную сложность для ключевых
   операций (поиск, вставка, удаление, извлечение min/max).
5. **Напиши алгоритм**, используя эту структуру.
6. **Проверь**, не ухудшается ли сложность из-за дополнительных операций (
   например, вызов `sort` внутри цикла).

## Главный совет для тренировки

Решив задачу, задай себе три вопроса:

- **Какая сложность у моего решения** (время и память)?
- **Можно ли было использовать другую структуру данных, чтобы улучшить сложность
  **?
- **Почему автор решения использовал именно этот подход**?

Со временем у тебя сформируются «рефлексы»: видишь задачу на поиск дубликатов →
сразу думаешь `HashSet`, видишь `k` самых частых → куча, видишь `k` самых
маленьких → куча или сортировка, видишь отсортированный массив → бинарный поиск.

И помни: **структура данных — это инструмент, алгоритм — это план, сложность —
это бюджет**. Если бюджет маленький (n большое), выбирай самые быстрые
структуры (хеш-таблицы, кучи) и алгоритмы с O(n log n) или O(n). Если бюджет
большой (n маленькое), можно позволить себе простые массивы и перебор.

# Признаки, по которым можно в задаче выбрать алгоритм

Отлично, давай соберём всё в единую практическую карту. Ниже — **система
признаков**, по которым ты можешь быстро определить, какой алгоритм или
структуру данных применять.

## 1. Признаки, указывающие на конкретную структуру данных

| Если в задаче...                                                                                | Это признак...                    | Используй                   |
|-------------------------------------------------------------------------------------------------|-----------------------------------|-----------------------------|
| нужно быстро проверять, *был ли элемент уже* (уникальность, дубликаты)                          | поиск в коллекции                 | `HashSet`, `HashMap`        |
| нужно часто искать элемент в *отсортированном* массиве                                          | бинарный поиск                    | `binarySearch()` или ручной |
| нужно всегда получать *минимальный/максимальный* элемент, причём элементы добавляются/удаляются | динамическая куча                 | `PriorityQueue`             |
| нужно обрабатывать данные в порядке *LIFO* (последним пришёл — первым ушёл)                     | стек                              | `ArrayDeque` (push/pop)     |
| нужно обрабатывать в порядке *FIFO* (первым пришёл — первым ушёл)                               | очередь                           | `ArrayDeque` (offer/poll)   |
| нужно быстро вставлять/удалять в середине (но не частый поиск)                                  | связный список                    | `LinkedList` (редко нужен)  |
| ключи должны быть упорядочены (например, получить все ключи в диапазоне)                        | дерево                            | `TreeMap`, `TreeSet`        |
| нужно ответить на много запросов *суммы на подотрезке* без изменений                            | префиксные суммы                  | массив префиксов            |
| нужно ответить на много запросов *суммы на подотрезке* с изменениями элементов                  | дерево отрезков / Фенвика         | `SegmentTree`, `BIT`        |
| нужно объединять множества и проверять связность                                                | система непересекающихся множеств | DSU (Union-Find)            |

## 2. Признаки, указывающие на категорию алгоритма

### 🧩 Перебор / бэктрекинг (Backtracking)

- **Признаки**: «все возможные комбинации», «все перестановки», «все
  подмножества», «найти все пути», «расстановка ферзей», «судоку».
- **Ограничения**: n ≤ 20 (иначе 2ⁿ слишком большая).
- **Структура**: рекурсия + массив для состояния.

### 🏃‍♂️ Жадный алгоритм (Greedy)

- **Признаки**: «минимальное количество монет/шагов», «максимальная выгода»,
  «назначение задач», «выбрать максимум непересекающихся интервалов»,
  «наименьшее количество опозданий».
- **Ключевая фраза**: «локально оптимальный выбор ведёт к глобальному оптимуму».
- **Типичный подход**: сортировка + проход с выбором лучшего кандидата.

### 🧠 Динамическое программирование (DP)

- **Признаки**:
    - «максимальная / минимальная / количество способов» (задача оптимизации или
      подсчёта).
    - «можно брать/не брать» (рюкзак).
    - «подпоследовательность», «подотрезок» (LCS, LIS, палиндромы).
    - «сколько способов добраться / сделать».
    - «true/false с перебором вариантов».
- **Ограничения**: обычно n ≤ 1000 для O(n²), n ≤ 10⁵ для O(n) с оптимизацией.
- **Признак, что НЕ DP**: можно жадным или формулой.

### ⚔️ Два указателя (Two pointers)

- **Признаки**: отсортированный массив + нужно найти пару/тройку с заданной
  суммой, или сравнить два массива, или «слияние», или «удалить дубликаты».
- **Скользящее окно (Sliding Window)**: подмассив / подстрока с условием (сумма,
  уникальные символы, длина), «найти максимальную длину…», «содержит все
  символы…».

### 🔍 Бинарный поиск (Binary search) — не только по массиву

- **Признаки**: отсортированный массив (явно или неявно), «найти X»,
  «минимальное значение, при котором выполняется условие» — бинарный поиск по
  ответу.
- **Фразы**: «наибольшее значение, при котором …», «первое вхождение», «можно ли
  получить сумму меньше K», «проверить, возможно ли за время M».

### 📊 Хеш-таблицы (Hash Maps / Sets)

- **Признаки**: «подсчитать частоту», «проверить наличие», «сгруппировать по
  ключу», «найти дубликаты», «пересечение массивов».
- **Золотое правило**: если тебе нужно быстро найти или запомнить что-то по
  значению — бери `HashMap`.

### 🌐 Графы (BFS / DFS / DSU / Дейкстра)

- **Признаки**: «комнаты / острова / клетки», «связность», «кратчайший путь» (
  BFS — для невзвешенного, Дейкстра — для взвешенного), «родительские
  отношения», «зависимости» (топологическая сортировка).
- **Структуры**: матрица → граф клеток; список рёбер; список смежности.

### 📈 Сортировка + что-то

- **Признаки**: почти любая задача, где важен относительный порядок элементов (
  интервалы, слияние, поиск пар с условием, жадные алгоритмы). Часто сортировка
  даёт снижение сложности с O(n²) до O(n log n).

## 3. Как применить этот список к конкретной задаче (пошагово)

1. **Прочитай задачу и выдели ключевые слова** (из колонки «признаки» выше).
2. **Посмотри на ограничения** — отсекает ли это перебор (n маленькое) или
   требует O(n log n) / O(n).
3. **Попробуй сопоставить с категорией**:
    - «все комбинации» → backtracking.
    - «максимум/минимум без перебора» → вероятно, жадный или DP.
    - «подстрока, подмассив» → скользящее окно или префиксные суммы.
    - «проверка наличия пары» → два указателя (если отсортирован) или HashMap.
    - «ищем значение с условием» → бинарный поиск по ответу.
4. **Если несколько кандидатов** — проверь, выполняются ли свойства (жадный
   работает только для определённых задач, DP — всегда, но дороже).
5. **Дальше** — реализуй, используя подходящие структуры данных (массив,
   хеш-таблица, куча, очередь).

## 5. Практический пример: как срабатывают признаки

**Задача:** «Дан массив целых чисел и целевая сумма. Вернуть индексы двух чисел,
которые в сумме дают цель».

- **Признаки:**
    - «найти пару» → два указателя? Но массив не сказано, что отсортирован.
    - «проверить наличие дополнения» → HashMap.
    - Ограничения: n до 10⁴? Можно O(n²) — но обычно больше, хотим O(n).
- **Вывод:** HashMap, один проход.

**Задача:** «Найти максимальную длину подстроки без повторяющихся символов».

- **Признаки:** «подстрока», «без повторяющихся» → скользящее окно с двумя
  указателями и HashSet для повторов.
- Сложность O(n).

**Задача:** «Найти k-й по величине элемент в массиве».

- **Признаки:** «k-й», «наибольший» → можно отсортировать O(n log n), но лучше
  использовать кучу (PriorityQueue) размером k: O(n log k).
- Если k маленькое, можно и кучу; если k близко к n, можно quickselect O(n) в
  среднем.

**Задача:** «Дан массив из 0 и 1, нужно найти самую длинную непрерывную
подпоследовательность с равным количеством 0 и 1».

- **Признаки:** «подмассив», «равное количество» → замена 0 на -1, префиксные
  суммы + HashMap для поиска одинаковых сумм.

Со временем ты начнёшь видеть эти паттерны автоматически. Моя рекомендация:
решив задачу, загляни в раздел «Solutions» / «Discuss» на LeetCode и посмотри,
как люди называют использованный паттерн. Это закрепит связку «признак →
алгоритм».
