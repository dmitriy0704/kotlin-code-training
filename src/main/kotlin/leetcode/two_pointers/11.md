# 11. Container With Most Water

## Условие

Вам дан целочисленный массив height длиной n. Нарисовано n вертикальных линий,
конечные точки которых i-й линии находятся в точках (i, 0) и (i, height[i]).

Найдите две прямые, которые вместе с осью x образуют контейнер, так что в этом
контейнере содержится наибольшее количество воды.

Верните максимальное количество воды, которое может вместить контейнер.

Обратите внимание, что контейнер нельзя наклонять.

Example 1:

![ex_11.jpg](../../../../../imgs/ex_11.jpg)

Input: height = [1,8,6,2,5,4,8,3,7]
Output: 49

Пояснение: Вертикальные линии выше представлены массивом [1,8,6,2,5,4,8,3,7]. В
этом случае максимальная площадь воды (синяя секция), которую может вместить
контейнер, составляет 49.

Example 2:

Input: height = [1,1]
Output: 1

## Решение

Отлично, переходим к **Leetcode 11. Container With Most Water** — классика двух
указателей с концов. Это одна из самых частых задач на собеседованиях, потому
что требует не только написать код, но и объяснить, почему предложенный жадный
подход корректен.

---

## Условие задачи

Дан массив `height` длины `n`, где `height[i]` — высота вертикальной линии в
точке `i`. Нужно найти две линии, которые вместе с осью X образуют контейнер,
вмещающий **максимальное количество воды**.  
Вода не выливается, поэтому объём (площадь) ограничен **меньшей из двух высот**,
а ширина — это расстояние между индексами.  
Формула: `area = (right - left) * min(height[left], height[right])`.  
Вернуть максимальную площадь.

---

## Интуиция и два указателя

Простой перебор всех пар дал бы O(n²). Но здесь работает **жадный подход с двух
концов**:

- Ставим `left = 0`, `right = n - 1`.
- На каждом шаге вычисляем текущую площадь, обновляем максимум.
- Затем **сдвигаем указатель с меньшей высотой** (если
  `height[left] < height[right]`, то `left++`, иначе `right--`).

Почему так?  
Площадь ограничена меньшей высотой. Если мы сдвинем указатель с **большей**
высотой, то ширина уменьшится, а высота не может стать больше текущего
минимума (она либо останется той же, либо уменьшится). Значит, площадь точно не
увеличится. Единственный шанс найти большую площадь — попытаться увеличить *
*минимальную** высоту, сдвигая указатель с меньшей стороной. Это позволяет за
один проход проверить все перспективные варианты.

---

## Реализация на Kotlin

```kotlin
fun maxArea(height: IntArray): Int {
    var left = 0
    var right = height.size - 1
    var maxArea = 0

    while (left < right) {
        // вычисляем площадь текущего контейнера
        val width = right - left
        val minHeight =
            if (height[left] < height[right]) height[left] else height[right]
        val area = width * minHeight
        maxArea = maxOf(maxArea, area)

        // сдвигаем указатель с меньшей высотой
        if (height[left] < height[right]) {
            left++
        } else {
            right--
        }
    }
    return maxArea
}
```

**Кратко:**

- Используем `maxOf` для обновления максимума.
- Сравниваем высоты и сдвигаем соответствующий указатель.
- Если высоты равны, можно сдвинуть любой (обычно правый, но это не влияет на
  результат).

## Пример работы

`height = [1,8,6,2,5,4,8,3,7]`

- left=0 (1), right=8 (7) → ширина=8, высота=1 → площадь=8, max=8. Сдвигаем
  left (1<7) → left=1.
- left=1 (8), right=8 (7) → ширина=7, высота=7 → площадь=49, max=49. Сдвигаем
  right (8>7) → right=7.
- left=1 (8), right=7 (3) → ширина=6, высота=3 → площадь=18. Сдвигаем right →
  right=6.
- left=1 (8), right=6 (8) → ширина=5, высота=8 → площадь=40. Сдвигаем right (
  можно любой) → right=5.
- left=1 (8), right=5 (4) → ширина=4, высота=4 → площадь=16. Сдвигаем right →
  right=4.
- left=1 (8), right=4 (5) → ширина=3, высота=5 → площадь=15. Сдвигаем right →
  right=3.
- left=1 (8), right=3 (2) → ширина=2, высота=2 → площадь=4. Сдвигаем right →
  right=2.
- left=1 (8), right=2 (6) → ширина=1, высота=6 → площадь=6.  
  Цикл завершается. Максимум = 49 (правильный ответ).

## Сложность

- **Время:** O(n) — один проход, каждый указатель двигается только в одну
  сторону.
- **Память:** O(1) — только две переменные.

---

## Почему это работает (доказательство)

Допустим, на некотором шаге у нас `height[left] < height[right]`. Мы сдвигаем
`left` вправо.  
Может ли существовать оптимальный контейнер, в котором `left` остаётся на месте,
а `right` смещается влево (т.е. мы бы не сдвигали `left`)?  
Ширина уменьшится, а высота не может стать больше `height[left]`, потому что
левая стенка фиксирована и является ограничением. Значит, любая такая пара будет
иметь площадь не больше текущей (где `right` был максимально удалён). Поэтому мы
безопасно отбрасываем все варианты с текущим `left` и переходим к следующей
возможной левой стенке. Аналогично для случая `height[right] < height[left]`.  
Таким образом, мы не пропускаем глобальный максимум.

---

## Частые ошибки

- Использовать `min(height[left], height[right])` каждый раз – нормально, но
  можно вычислить один раз для скорости.
- Забыть обновлять `maxArea` до сдвига – важно вычислить площадь для текущей
  пары.
- Сдвигать не тот указатель (например, всегда сдвигать `left`), что приведёт к
  неверному ответу.

---

## Дополнительные вариации

- Если массив содержит отрицательные высоты? В условии их нет, но если бы были,
  логика нарушилась бы (но это не рассматривается).
- Можно решить и с помощью стека, но два указателя — самое элегантное решение.
