# 125. Valid Palindrome

## Условие

Фраза называется палиндромом, если после преобразования всех заглавных букв в
строчные и удаления всех небуквенно-цифровых символов она читается одинаково как
в прямом, так и в обратном порядке. К буквенно-цифровым символам относятся буквы
и цифры.

Если задана строка s, верните true, если она является палиндромом, или false в
противном случае.

Example 1:
Input: s = "A man, a plan, a canal: Panama"
Output: true
Explanation: "amanaplanacanalpanama" is a palindrome.

Example 2:
Input: s = "race a car"
Output: false
Explanation: "raceacar" is not a palindrome.

Example 3:
Input: s = " "
Output: true
Пояснение: s — это пустая строка "" после удаления небуквенно-цифровых символов.
Поскольку пустая строка читается одинаково как вперед, так и назад, она является
палиндромом.

Constraints:

1 <= s.length <= 2 * 10^5
s consists only of printable ASCII characters.

## Решение

Отлично! Давайте разберём **Leetcode 125. Valid Palindrome** (Проверка
палиндрома) прямо сейчас.

---

## Условие задачи

Дана строка `s`. Нужно вернуть `true`, если она является палиндромом **без учёта
регистра** и **игнорируя все не буквенно-цифровые символы** (пробелы, знаки
препинания и т.д.).  
Примеры:

- `"A man, a plan, a canal: Panama"` → `true`
- `"race a car"` → `false`
- `" "` → `true` (пустая строка или только пробелы)

---

## Базовый подход – два указателя с концов

1. Ставим указатель `left` в начало (0), `right` в конец (`length - 1`).
2. Пока `left < right`:
    - Пропускаем символы, которые не являются буквами или цифрами (двигаем
      соответствующий указатель внутрь).
    - Сравниваем символы (в нижнем регистре). Если не равны – возвращаем
      `false`.
    - Если равны – двигаем оба указателя внутрь.
3. Если цикл завершился – строка палиндром.

**Почему это работает?**  
Мы проверяем только значимые символы, и движемся от краёв к центру. Как только
находим несовпадение – строка не палиндром.

---

## Реализация на Kotlin

### Вариант 1 (чистые указатели без выделения памяти)

Этот способ оптимален по памяти – O(1), кроме самой строки.

```kotlin
fun isPalindrome(s: String): Boolean {
    var left = 0
    var right = s.length - 1

    while (left < right) {
        // Пропускаем не-буквенно-цифровые слева
        while (left < right && !s[left].isLetterOrDigit()) {
            left++
        }
        // Пропускаем не-буквенно-цифровые справа
        while (left < right && !s[right].isLetterOrDigit()) {
            right--
        }

        // Сравниваем символы без учёта регистра
        if (s[left].lowercaseChar() != s[right].lowercaseChar()) {
            return false
        }

        // Сдвигаем внутрь
        left++
        right--
    }
    return true
}
```

**Обратите внимание:**

- Метод `isLetterOrDigit()` есть у `Char` в Kotlin.
- Для приведения к нижнему регистру используем `lowercaseChar()`.
- Внутренние `while` используют `left < right`, чтобы не выйти за границы, если
  вся строка невалидная – но в таком случае внешний цикл остановится.

---

### Вариант 2 (более краткий, но с дополнительной памятью)

Можно отфильтровать строку, оставив только буквы/цифры, перевести в нижний
регистр и сравнить с реверсом.

```kotlin
fun isPalindrome(s: String): Boolean {
    val filtered = s.filter { it.isLetterOrDigit() }.lowercase()
    return filtered == filtered.reversed()
}
```

**Плюсы:** очень читаемо, легко.  
**Минусы:** создаёт новые строки – память O(n). На Leetcode это проходит, но
если цель – научиться технике указателей, первый вариант предпочтительнее.

---

## Разбор примера

Возьмём строку: `"A man, a plan, a canal: Panama"`

- `left = 0` ('A'), `right = 29` ('a')
- Пропускаем невалидные: слева 'A' – валидный, справа 'a' – валидный.
- Сравниваем 'a' и 'a' – ок.
- Двигаем: left=1 (' ' – пробел), right=28 ('m')
- Внутренние while: left пропустит пробел, станет 2 ('m'), справа останется 'm'.
- Сравниваем 'm' и 'm' – ок. И так далее.
- В конце left и right встретятся – возвращаем true.

---

## Сложность

- **Время:** O(n), где n – длина строки. Каждый символ обрабатывается не более
  двух раз (один раз каждым указателем).
- **Память:** O(1) для варианта с указателями (не считая входной строки).

---

## Частые ошибки новичков

1. Забывают пропускать невалидные символы – тогда `"race a car"` ложно выдаст
   false, хотя нужно true.
2. Сравнивают без приведения регистра – нужно использовать `lowercaseChar()` (
   или `equals` с `ignoreCase = true`).
3. Внутренние циклы пропускают только если `left < right`, иначе можно выйти за
   пределы (например, строка `",."` – тогда left дойдёт до right, и сравнение не
   произойдёт).
4. Используют `s[left].lowercase()` – это возвращает строку, лучше использовать
   `lowercaseChar()` для Char.

---

## Альтернативный вариант сравнения с ignoreCase

Вместо `lowercaseChar()` можно использовать:

```kotlin
if (s[left].equals(s[right], ignoreCase = true)) {
    ...
}
```

Но этот метод доступен у `Char` через `equals` с `ignoreCase`, что тоже
работает. Однако `lowercaseChar()` более явный.
