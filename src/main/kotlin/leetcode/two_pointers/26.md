# 26. Remove Duplicates from Sorted Array

## Условие

Дан целочисленный массив nums, отсортированный в порядке неубывания. Необходимо
удалить дубликаты на месте таким образом, чтобы каждый уникальный элемент
встречался только один раз. Относительный порядок элементов должен оставаться
неизменным.

Пусть количество уникальных элементов в массиве nums равно k. После удаления
дубликатов верните количество уникальных элементов k.

Первые k элементов массива nums должны содержать уникальные числа в
отсортированном порядке. Остальные элементы после индекса k - 1 можно
игнорировать.

Пользовательский судья:

Судья проверит ваше решение с помощью следующего кода:

```code
int[] nums = [...]; // Input array
int[] expectedNums = [...]; // The expected answer with correct length

int k = removeDuplicates(nums); // Calls your implementation

assert k == expectedNums.length;
for (int i = 0; i < k; i++) {
    assert nums[i] == expectedNums[i];
}

```

Если все утверждения пройдут успешно, ваше решение будет принято.

Example 1:

Input: nums = [1,1,2]
Output: 2, nums = [1,2,_]
Пояснение: Ваша функция должна возвращать k = 2, при этом первые два элемента
массива nums должны быть равны 1 и 2 соответственно.

Неважно, что вы оставите после возвращаемого значения k (поэтому это
подчеркивания).

Constraints:

1 <= nums.length <= 3 * 104
-100 <= nums[i] <= 100
nums is sorted in non-decreasing order.

## Решение

Отлично, переходим к **Leetcode 26. Remove Duplicates from Sorted Array** (
Удаление дубликатов из отсортированного массива).  
Задача: дан отсортированный массив `nums`, нужно удалить дубликаты **на месте (
in-place)**, чтобы каждый элемент встречался только один раз. Вернуть новую
длину массива (первые `k` элементов должны содержать уникальные значения,
остальное не важно).  
Требуется O(1) дополнительной памяти.

## Что такое in-place (на месте)?

**In-place** означает, что мы модифицируем исходную структуру данных (массив),
не создавая новую копию (или создавая только несколько переменных для индексов).
Мы не выделяем новый массив размером n, а перезаписываем элементы внутри
исходного. Это экономит память — O(1) вместо O(n).  
В этой задаче мы можем сдвигать уникальные элементы в начало массива, затирая
старые дубликаты.

## Два указателя: медленный (write) и быстрый (read)

- **`i` (медленный)** — указывает на позицию, куда мы будем записывать следующий
  уникальный элемент. Изначально `i = 0`.
- **`j` (быстрый)** — проходит по массиву от `1` до конца, ища новый уникальный
  элемент (отличающийся от `nums[i]`).

Поскольку массив отсортирован, дубликаты идут подряд. Когда
`nums[j] != nums[i]`, мы нашли новый элемент, увеличиваем `i` на 1 и записываем
`nums[j]` в новую позицию `i`. Так мы собираем уникальные значения в начале.

## Алгоритм шаг за шагом

1. Если массив пустой или длиной 0, возвращаем 0 (хотя по условию длина может
   быть 0). Иначе устанавливаем `i = 0`.
2. Запускаем цикл `for (j in 1 until nums.size)`.
3. Если `nums[j] != nums[i]`:
    - Увеличиваем `i++` (сдвигаем "место записи").
    - Копируем `nums[j]` в `nums[i]`.
4. После окончания цикла возвращаем `i + 1` — это количество уникальных
   элементов.

**Важно:** Мы не удаляем элементы физически, просто перезаписываем первые `k`
позиций. Остаток массива остаётся без изменений, но нас интересует только новая
длина.

## Код на Kotlin

```kotlin
fun removeDuplicates(nums: IntArray): Int {
    if (nums.isEmpty()) return 0

    var i = 0 // медленный указатель — место для вставки уникального элемента

    for (j in 1 until nums.size) { // быстрый указатель — обходит массив
        if (nums[j] != nums[i]) {
            i++ // переходим к следующей позиции для записи
            nums[i] = nums[j] // записываем новый уникальный элемент
        }
    }
    return i + 1 // длина уникальной части
}
```

## Пример работы

Вход: `[0,0,1,1,1,2,2,3,3,4]`

- `i = 0`, `j = 1`: nums[1]=0 равно nums[0]=0 → пропускаем.
- `j = 2`: nums[2]=1 ≠ nums[0]=0 → `i = 1`, nums[1]=1 → массив
  `[0,1,1,1,1,2,2,3,3,4]`
- `j = 3`: nums[3]=1 равно nums[1]=1 → пропускаем.
- `j = 4`: nums[4]=1 равно → пропускаем.
- `j = 5`: nums[5]=2 ≠ nums[1]=1 → `i = 2`, nums[2]=2 → `[0,1,2,1,1,2,2,3,3,4]`
- `j = 6`: nums[6]=2 равно nums[2]=2 → пропускаем.
- `j = 7`: nums[7]=3 ≠ nums[2]=2 → `i = 3`, nums[3]=3 → `[0,1,2,3,1,2,2,3,3,4]`
- `j = 8`: nums[8]=3 равно → пропускаем.
- `j = 9`: nums[9]=4 ≠ nums[3]=3 → `i = 4`, nums[4]=4 → `[0,1,2,3,4,2,2,3,3,4]`
- Цикл завершён. Возвращаем `i+1 = 5`. Первые 5 элементов: 0,1,2,3,4 —
  уникальные.

## Почему это in-place и O(1) памяти?

Мы используем только две целочисленные переменные `i` и `j`. Никаких
дополнительных массивов или коллекций. Перезапись происходит внутри `nums`. Хотя
мы меняем порядок остатка (после индекса `i` там остаются старые значения), это
не важно, потому что мы возвращаем только новую длину.

## Связь с темой двух указателей

Здесь два указателя движутся в одном направлении (быстрый всегда впереди). Это *
*однонаправленный паттерн двух указателей**, часто называемый "медленный и
быстрый". В отличие от встречных указателей (как в палиндроме), здесь оба
стартуют с начала, и медленный отстаёт.

## Что ещё стоит учесть

- Массив уже **отсортирован** — это ключевое условие, иначе алгоритм бы не
  работал.
- Если массив из одного элемента — `i = 0`, цикл не выполняется, возвращаем 1.
- Можно написать и через `while`, но `for` здесь читается лучше.
