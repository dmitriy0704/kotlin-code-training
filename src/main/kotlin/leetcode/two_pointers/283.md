# 283. Move Zeroes

## Условие

Дана целочисленная матрица nums. Необходимо переместить все нули в конец
матрицы, сохраняя при этом относительный порядок ненулевых элементов.

Обратите внимание, что это необходимо сделать непосредственно в массиве, не
создавая его копию.

Example 1:
Input: nums = [0,1,0,3,12]
Output: [1,3,12,0,0]

Example 2:
Input: nums = [0]
Output: [0]

Constraints:
1 <= nums.length <= 104
-231 <= nums[i] <= 231 - 1

## Решение:

Отлично, твоя интуиция абсолютно верна! Задача **283. Move Zeroes** (Переместить
нули) — классика на два указателя. Условие: дан массив `nums`, нужно переместить
все нули в конец, сохраняя относительный порядок ненулевых элементов. Делать
in-place, минимизировать операции.

Ты правильно заметил, что можно менять местами ноль и ненулевой элемент, сдвигая
нули вправо. Но стандартный подход чуть проще и эффективнее — он **не требует
обмена на каждом шагу**, а только перезаписывает и заполняет нулями.

---

## Суть алгоритма (медленный и быстрый указатели)

- **`slow`** (медленный) — указывает на позицию, куда мы будем ставить следующий
  ненулевой элемент (изначально 0).
- **`fast`** (быстрый) — бежит по массиву от 0 до конца, ищет ненулевые
  элементы.

**Логика:**

1. Проходим `fast` по массиву.
2. Если `nums[fast] != 0`, то:
    - Меняем местами `nums[slow]` и `nums[fast]` (или просто присваиваем
      `nums[slow] = nums[fast]`, а потом `nums[fast] = 0`, если `slow != fast`).
    - Увеличиваем `slow`.
3. В конце все нули оказываются после `slow`.

---

## Реализация на Kotlin (с обменом)

```kotlin
fun moveZeroes(nums: IntArray): Unit {
    var slow = 0
    for (fast in nums.indices) {
        if (nums[fast] != 0) {
            // Меняем местами элементы
            val temp = nums[slow]
            nums[slow] = nums[fast]
            nums[fast] = temp
            slow++
        }
    }
}
```

**Почему это работает?**

- `slow` всегда указывает на первый ноль в текущей обработанной части (или на
  позицию после всех ненулевых, если нулей нет).
- Когда `fast` находит ненулевой элемент, мы обмениваем его с элементом на
  `slow` (который обычно ноль, если были встречены нули). Так мы проталкиваем
  ноль вперёд, а ненулевой элемент остаётся слева. Порядок ненулевых
  сохраняется, потому что мы идём слева направо и вставляем их по порядку.

---

## Альтернатива (без обмена, с присваиванием)

Можно сначала записать все ненулевые элементы в начало, а затем заполнить
оставшуюся часть нулями. Это иногда проще для понимания, но требует двух
проходов (или одного с подсчётом). Однако стандартный обмен — один проход и O(1)
памяти.

---

## Твой вариант (перестановка нуля и ненулевого)

Ты правильно описал идею: "если элемент не равен 0 — записываем его на позицию
нуля, а 0 записываем на позицию элемента не равного 0". Это как раз то, что
делает обмен. Например, массив `[0,1,0,3,12]`:

- fast=1, nums[1]=1 ≠0 → меняем с nums[0]=0 → `[1,0,0,3,12]`, slow=1.
- fast=3, nums[3]=3 ≠0 → меняем с nums[1]=0 → `[1,3,0,0,12]`, slow=2.
- fast=4, nums[4]=12 ≠0 → меняем с nums[2]=0 → `[1,3,12,0,0]`, slow=3.
  Всё верно.

---

## Почему обмен предпочтительнее, чем простой сдвиг?

Если бы мы сдвигали все нули вправо (как в пузырьковой сортировке), это было бы
O(n²). А здесь мы делаем один проход — O(n).

---

## Сложность

- **Время:** O(n) — один проход.
- **Память:** O(1) — только две переменные.

---

## Что ещё стоит знать

- Эта задача — вариация тех же двух указателей, что и в Remove Element. Только
  там мы удаляли `val`, а здесь мы отделяем нули.
- Если порядок ненулевых не важен, можно было бы использовать встречные
  указатели (как в Remove Element с конца), но здесь порядок важен, поэтому
  только однонаправленный метод.

---

## Готовый код с комментариями

```kotlin
fun moveZeroes(nums: IntArray): Unit {
    var insertPos = 0 // медленный указатель
    for (num in nums) { // быстрый указатель (перебираем элементы)
        if (num != 0) {
            nums[insertPos] = num
            insertPos++
        }
    }
    // Заполняем оставшиеся позиции нулями
    for (i in insertPos until nums.size) {
        nums[i] = 0
    }
}
```

Этот вариант тоже корректен, но делает две записи на каждый ненулевой элемент (
сначала запись, потом обнуление), тогда как обмен делает две записи только при
обнаружении нуля. Оба принимаются.
