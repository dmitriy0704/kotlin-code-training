# 11. Container With Most Water

## Условие

Вам дан целочисленный массив height длиной n. Нарисовано n вертикальных линий,
конечные точки которых i-й линии находятся в точках (i, 0) и (i, height[i]).

Найдите две прямые, которые вместе с осью x образуют контейнер, так что в этом
контейнере содержится наибольшее количество воды.

Верните максимальное количество воды, которое может вместить контейнер.

Обратите внимание, что контейнер нельзя наклонять.

Example 1:

![ex_11.jpg](../../../../../../imgs/ex_11.jpg)

Input: height = [1,8,6,2,5,4,8,3,7]
Output: 49

Пояснение: Вертикальные линии выше представлены массивом [1,8,6,2,5,4,8,3,7]. В
этом случае максимальная площадь воды (синяя секция), которую может вместить
контейнер, составляет 49.

Example 2:

Input: height = [1,1]
Output: 1

## Решение

Дан массив неотрицательных целых чисел height, где каждое число — это высота
вертикальной линии на графике. Расстояние между соседними линиями равно 1.

Нужно выбрать две линии так, чтобы вместе с осью \(X\) они образовали контейнер,
который вмещает наибольшее количество воды. Функция должна вернуть этот
максимальный объем.

## Как считается объем воды между двумя линиями?

Объем воды — это площадь прямоугольника. Она вычисляется по формуле:

```text
        Объем = Ширина X Высота
```

1. Ширина — это расстояние между индексами двух линий: right - left.
2. Высота ограничена более короткой из двух линий (иначе вода просто выльется
   через край). То есть minOf(height[left], height[right]).

## Стратегия: Два встречных указателя

Решать задачу через перебор всех возможных пар линий (два цикла for) слишком
медленно — это займет O(N^2) времени и вызовет ошибку Time Limit Exceeded.
Метод двух указателей позволяет решить задачу за один проход O(N):

1. Ставим левый указатель left в самое начало массива (0), а правый right — в
   самый конец (height.size - 1).
2. На этом этапе у нас максимально возможная ширина контейнера. Мы считаем объем
   воды и запоминаем его.
3. Теперь нам нужно сузить контейнер, чтобы попытаться найти более высокие
   линии. Какую из двух границ двигать?

    * Двигаем ту линию, которая меньше (ниже)!
    * Почему? Если мы сдвинем более высокую линию, ширина контейнера уменьшится,
      а высота точно не станет больше текущего минимума. Мы гарантированно
      потеряем в объеме. А вот если мы сдвинем короткую линию, у нас появляется
      шанс встретить внутри графика гораздо более высокую стенку, которая
      компенсирует потерю ширины.

## Код на Kotlin

Вот лаконичное и максимально быстрое решение:

```kotlin
//import kotlin.math.maximport kotlin.math.min

class Solution {
    fun maxArea(height: IntArray): Int {
        var maxWater = 0
        var left = 0
        var right = height.size - 1

        while (left < right) {
            // 1. Вычисляем ширину контейнера
            val width = right - left

            // 2. Находим эффективную высоту (по меньшей стене)
            val currentHeight = min(height[left], height[right])

            // 3. Считаем текущий объем и "жадно" обновляем максимум
            val currentWater = width * currentHeight
            maxWater = max(maxWater, currentWater)

            // 4. Двигаем указатель, который стоит на более низкой стене
            if (height[left] < height[right]) {
                left++
            } else {
                right--
            }
        }

        return maxWater
    }

}

```

## Пошаговый разбор на примере: height = [1, 8, 6, 2, 5, 4, 8, 3, 7]

1. Шаг 1: left = 0 (высота 1), right = 8 (высота 7).

    * Ширина = 8 - 0 = 8. Высота = min(1, 7) = 1.
    * Объем = 8 * 1 = 8. maxWater = 8.
    * Так как height[left] < height[right] (1 < 7), двигаем левый указатель:
      left++ (становится 1).

2. Шаг 2: left = 1 (высота 8), right = 8 (высота 7).

    * Ширина = 8 - 1 = 7. Высота = min(8, 7) = 7.
    * Объем = 7 * 7 = 49. maxWater = 49.
    * Так как 8 > 7, двигаем правый: right-- (становится 7).

3. Шаг 3: left = 1 (высота 8), right = 7 (высота 3).

    * Ширина = 7 - 1 = 6. Высота = min(8, 3) = 3.
    * Объем = 6 * 3 = 18. Рекорд 49 устоял.
    * Двигаем правый: right-- (становится 6).

... Указатели будут сближаться, пока на left = 1 (высота 8) и right = 6
(высота 8) они не дадут еще один большой объем 5 * 8 = 40, но рекорд 49
так и останется непревзойденным.

## Сложность

* Времени: O(N) — мы проходим по массиву один раз, сближая указатели.
* Памяти: O(1) — используется фиксированное количество переменных для хранения
  индексов и объемов.
