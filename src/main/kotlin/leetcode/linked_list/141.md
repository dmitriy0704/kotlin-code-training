# 141. Linked List Cycle

## Условие

Дано имя head связанного списка. Определите, содержит ли связанный список цикл.

Цикл в связанном списке возникает, если в списке есть узел, до которого можно
снова добраться, непрерывно следуя указателю next. Внутри системы pos
используется для обозначения индекса узла, к которому подключен указатель next
указателя tail. Обратите внимание, что pos не передается в качестве параметра.

Возвращает true, если в связанном списке есть цикл. В противном случае
возвращает false.

Example 1:

```text
[3] ---> [2] ---> [0] ---> [-4]
          ^                 |
          |_________________|

```

Input: head = [3,2,0,-4], pos = 1
Output: true
Explanation: В связанном списке существует цикл, в котором хвост соединяется с
первым узлом (с индексом 0).

Example 2:

Input: head = [1,2], pos = 0
Output: true
Explanation: В связанном списке существует цикл, в котором хвост соединяется с
нулевым узлом.

Example 3:

Input: head = [1], pos = -1
Output: false
Explanation: There is no cycle in the linked list.

Constraints:

The number of the nodes in the list is in the range [0, 104].
-105 <= Node.val <= 105
pos is -1 or a valid index in the linked-list.


## Решение:

Отлично, задача **141. Linked List Cycle** — это классика, и она познакомит вас
с одним из самых элегантных алгоритмов в программировании: **алгоритмом Флойда
для поиска цикла** (он же «черепаха и заяц»).

---

## Суть задачи

Дан связный список. Нужно определить, есть ли в нём цикл (кольцо). Цикл — это
ситуация, когда, переходя по ссылкам `next`, вы когда-нибудь вернётесь в уже
посещённый узел, и обход никогда не закончится.

---

## Методика: два указателя (Fast & Slow)

Используйте два указателя:

- **`slow`** — двигается на **один** шаг за итерацию.
- **`fast`** — двигается на **два** шага за итерацию.

**Идея:** Если в списке есть цикл, то `fast` рано или поздно догонит `slow` (как
на круговой дорожке). Если цикла нет, то `fast` первым достигнет `null` и
завершит цикл.

**Почему это работает?**  
Представьте бегунов на круговом треке. Один бежит в два раза быстрее другого.
Они обязательно встретятся, потому что быстрый бегун будет постоянно обгонять
медленного. Относительная скорость равна 1 (быстрый догоняет медленного на один
шаг за итерацию). Если трек замкнут, они сойдутся.

---

## Решение на Kotlin (итеративное)

```kotlin
fun hasCycle(head: ListNode?): Boolean {
    var slow = head
    var fast = head

    while (fast != null && fast.next != null) {
        slow = slow?.next          // на 1 шаг
        fast = fast.next?.next     // на 2 шага
        if (slow == fast) {
            return true            // встретились — цикл есть
        }
    }
    return false                   // дошли до конца — цикла нет
}
```

### Разбор кода

- **Инициализация:** оба указателя стартуют с головы.
- **Условие цикла:** `fast != null && fast.next != null` — мы проверяем, что у
  `fast` есть возможность сделать два шага. Если `fast` или `fast.next` равен
  `null`, то список кончается, цикла нет.
- **Шаг:** перемещаем `slow` на один узел, `fast` — на два.
- **Проверка:** если указатели стали равны (ссылаются на один объект), значит,
  они встретились внутри цикла. Возвращаем `true`.
- **Завершение:** если вышли из цикла, значит, `fast` достиг конца — цикл
  отсутствует.

---

## Почему не нужен `dummy` или `prev`?

Здесь нет операций вставки/удаления, и голова не меняется. Нам просто нужно
обойти список без изменения структуры. Поэтому `dummy` не требуется.

---

## Сложность

- **Время:** O(n), где n — число узлов. В худшем случае (без цикла) быстрый
  указатель пройдёт все узлы за n/2 шагов. В случае цикла они встретятся
  максимум за n шагов.
- **Память:** O(1) — используем только два указателя.

---

## Альтернативный подход (не рекомендуется в интервью)

Можно использовать `HashSet` для хранения посещённых узлов:

```kotlin
fun hasCycle(head: ListNode?): Boolean {
    val visited = mutableSetOf<ListNode>()
    var curr = head
    while (curr != null) {
        if (visited.contains(curr)) return true
        visited.add(curr)
        curr = curr.next
    }
    return false
}
```

Это тоже O(n) по времени, но O(n) по памяти. В интервью почти всегда просят
алгоритм Флойда из-за его эффективности по памяти.

---

## Частые ошибки

1. **Забыть проверить `fast.next` на null.** Если написать просто
   `while (fast != null)`, то внутри `fast.next?.next` может вызвать ошибку,
   если `fast.next == null`. Поэтому условие должно быть
   `fast != null && fast.next != null`.
2. **Инициализировать `fast = head.next`.** Некоторые делают так, но это
   усложняет код и может привести к ошибкам на пустом списке. Стартовать с одной
   точки — проще и надёжнее.
3. **Пустой список** обрабатывается корректно: цикл не выполняется, возвращается
   `false`.
