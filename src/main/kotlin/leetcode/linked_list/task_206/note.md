# 206. Reverse Linked List

## Условие

Имея в начале односвязный список, переверните список и верните перевернутый
список.

Example 1:
Input: head = [1,2,3,4,5]
Output: [5,4,3,2,1]

Example 2:
Input: head = [1,2]
Output: [2,1]

## Решение

Суть задачи

Тебе дается голова связного списка: 1 -> 2 -> 3 -> 4 -> 5 -> null.

Нужно развернуть все стрелки в противоположную сторону, чтобы получилось:
null <- 1 <- 2 <- 3 <- 4 <- 5 (что эквивалентно 5 -> 4 -> 3 -> 2 -> 1 -> null).

Главная сложность — не потерять элементы в памяти в процессе разворота. Если ты
просто возьмешь узел 2 и направишь его next на 1, ты мгновенно потеряешь ссылку
на узел 3, и вся оставшаяся часть списка (3 -> 4 -> 5) сотрется из памяти
(Garbage Collector ее удалит).

Визуализация алгоритма (Три указателя)

Чтобы не терять узлы, нам понадобятся три переменные-указателя, которые будут
двигаться по списку:

1. prev (предыдущий) — куда должна указывать стрелка текущего узла.
2. current (текущий) — узел, чью стрелку мы разворачиваем прямо сейчас.
3. nextTmp (следующий/временный) — страховка, которая держит ссылку на
   оставшуюся часть списка.

Представь, что мы находимся в середине процесса на узле 2:

```text
  1 <- 2     3 -> 4 -> 5 -> null
  ^    ^     ^
  |    |     |
prev  curr  nextTmp

```

Мы временно запоминаем 3 в nextTmp. После этого мы можем безопасно развернуть
стрелку у 2 (направить её на 1). Затем мы просто сдвигаем prev и curr на один
шаг вправо.

## Код. Итеративный подход

Этот способ использует цикл while. Он самый эффективный: работает за O(N)
времени и занимает всего O(1) памяти (мы не создаем новые узлы, а просто
перекладываем существующие стрелки).

```kotlin
class Solution {
    fun reverseList(head: ListNode?): ListNode? {
        // Сюда будет смотреть стрелка текущего узла (сначала в null)
        var prev: ListNode? = null

        // Узел, который мы разворачиваем прямо сейчас
        var current = head
        
        // null -> 1 -> 2 -> 3 -> 4 -> 5 -> null

        while (current != null) {

            // 1. СТРАХОВКА: запоминаем, где остаток списка
            val nextTmp = current.next

            // 2. РАЗВОРОТ: направляем стрелку текущего узла назад
            current.next = prev

            // 3. СДВИГ: текущий узел становится "предыдущим" для следующего шага
            prev = current

            // 4. СДВИГ: переходим к следующему узлу из страховки
            current = nextTmp
        }

        // Когда current станет null, prev окажется на самом последнем (теперь первом) узле
        return prev
    }
}

```

## Пошаговый разбор на примере 1 -> 2 -> 3 -> null

Старт:

- prev = null,
- current = 1.

```text
 null <- 1     2  -> 3 -> null
  ^      ^     ^
  |      |     |
prev    curr  nextTmp
``` 

* Итерация 1 (работаем с узлом 1):

    1. nextTmp = curr.next - запоминает узел 2.
    2. current.next (узел 1) направляется на prev (null). Теперь первая связь
       оборвана: 1 -> null.
    3. prev сдвигается на узел 1.
    4. current переходит на nextTmp (узел 2).

Состояние списка: 1 -> null и оторванный хвост 2 -> 3 -> null. Но у нас
есть current, который стоит на 2!

```text
 null <- 1     2 ->  3 ->  null
         ^     ^     ^
         |     |     |
        prev  curr  nextTmp
``` 

* Итерация 2 (работаем с узлом 2):

    1. nextTmp запоминает узел 3.
    2. current.next (узел 2) направляется на prev (узел 1). Получилось: 2 ->
       1 -> null.
    3. prev сдвигается на узел 2.
    4. current переходит на nextTmp (узел 3).

Состояние списка: 2 -> 1 -> null и оторванный хвост 3 -> null.

```text
 null <- 1  <- 2     3 -> null
               ^     ^     ^
               |     |     |
              prev  curr  nextTmp
``` 

* Итерация 3 (работаем с узлом 3):

    1. nextTmp запоминает null (конец исходного списка).
    2. current.next (узел 3) направляется на prev (узел 2). Получилось: 3 ->
       2 -> 1 -> null.
    3. prev сдвигается на узел 3.
    4. current становится null.

```text
 null <- 1  <- 2 <- 3 <- null
                    ^     ^     
                    |     |     
                   prev  curr
``` 

Конец цикла. Метод возвращает prev (узел 3), который теперь является новой
головой развернутого списка.

Эту задачу также можно решить через рекурсию, но итеративный способ (через
while) считается более безопасным для продакшена, так как не переполняет стек
вызовов памяти.

## 🧠 Альтернатива: Рекурсивный подход

Иногда на собеседованиях просят: «А решите теперь то же самое, но без цикла —
через рекурсию».
Идея рекурсии в том, что мы доходим до самого конца списка, а затем
разворачиваем стрелки «на обратном пути», когда функции завершаются и выходят из
стека.

Вот как это выглядит на Kotlin:

```kotlin

class Solution {
    fun reverseList(head: ListNode?): ListNode? {
// Базовый случай: если список пустой или остался один узел, возвращаем его
        if (head == null || head.next == null) {
            return head
        }

        // Рекурсивно разворачиваем весь хвост начиная со 2-го элемента
        val newHead = reverseList(head.next)

        // Разворачиваем стрелку между текущим узлом (head) и следующим (head.next)
        head.next?.next = head
        head.next = null // Зануляем старую прямую стрелку

        return newHead
    }
}

```

Минус рекурсии: Она тратит O(N) памяти в стеке вызовов, поэтому для очень
длинных списков (миллионы элементов) может вызвать ошибку StackOverflowError.
Итеративный метод (через while) всегда безопаснее.
