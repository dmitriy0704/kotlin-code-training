# 21. Merge Two Sorted Lists

## Условие

Вам даны заголовки двух отсортированных связанных списков list1 и list2.

Объедините два списка в один отсортированный список. Список должен быть создан
путем объединения узлов первых двух списков.

Возвращает начало объединенного связанного списка.
(Return the head of the merged linked list.)

Example 1:

![ex_21.jpg](../../../../../imgs/ex_21.jpg)

Input: list1 = [1,2,4], list2 = [1,3,4]
Output: [1,1,2,3,4,4]

Example 2:
Input: list1 = [], list2 = []
Output: []

Example 3:
Input: list1 = [], list2 = [0]
Output: [0]

## Решение

Отлично, задача **21. Merge Two Sorted Lists** — это классика, и она
действительно проста, когда вы освоите главную методику. Давайте разберём её не
как код, а как **приём мышления**.

---

## Главная методика: «Слияние с фиктивной головой»

При слиянии двух отсортированных списков мы по сути делаем то же самое, что и в
сортировке слиянием (Merge Sort) — **проходим по обоим спискам одновременно,
всегда выбирая меньший элемент** и прикрепляя его к новому списку.

Но здесь есть техническая тонкость: как удобно строить новый список, не
заморачиваясь с особым случаем для самого первого узла?

**Ответ — фиктивный (dummy) узел.**

- Вы создаёте узел-пустышку, который не несёт полезного значения, но на него
  будет указывать `head` нового списка.
- Держите указатель `tail` (или `current`), который всегда указывает на
  последний добавленный узел.
- На каждом шаге сравниваете значения текущих узлов двух списков, меньший
  прикрепляете за `tail`, передвигаете `tail` и соответствующий указатель в
  исходном списке.
- Когда один из списков заканчивается, вы просто прикрепляете остаток другого
  списка к `tail` — и всё.

Этот подход **убирает все `if`-проверки на пустой начальный список**, потому что
dummy-узел всегда есть. В конце возвращаете `dummy.next` — это и есть голова
итогового списка.

## Решение на Kotlin с комментариями

```kotlin
/**
 * Пример узла, данный в задаче.
 * class ListNode(var `val`: Int) {
 *     var next: ListNode? = null
 * }
 */
fun mergeTwoLists(list1: ListNode?, list2: ListNode?): ListNode? {
    // Создаём фиктивный узел. Его значение не важно.
    val dummy = ListNode(-1)
    var tail: ListNode? =
        dummy // tail всегда указывает на последний добавленный узел

    var p1 = list1
    var p2 = list2

    // Пока оба списка не пусты, сравниваем и выбираем меньшее
    while (p1 != null && p2 != null) {
        if (p1.`val` <= p2.`val`) {
            tail?.next = p1   // прикрепляем узел из первого списка
            p1 = p1.next      // сдвигаем указатель первого
        } else {
            tail?.next = p2
            p2 = p2.next
        }
        tail = tail?.next     // сдвигаем tail на только что добавленный узел
    }

    // Если один из списков ещё не закончился, просто прикрепляем его остаток
    tail?.next = p1 ?: p2

    // Возвращаем настоящую голову нового списка
    return dummy.next
}
```

---

## Что здесь важно для понимания?

1. **Два указателя** (`p1`, `p2`) — они сканируют исходные списки, и мы не
   создаём новые узлы, а **переиспользуем** существующие. Это экономит память (
   сложность по памяти O(1) в дополнение к уже имеющимся узлам).

2. **Фиктивный узел** — это не просто хитрость, а **стандартный паттерн** для
   всех задач, где голова результата может меняться (удаление, разбиение,
   слияние). Запомните его раз и навсегда.

3. **Остаток** — когда один список пуст, мы просто «пришиваем» оставшийся кусок
   второго списка. Это работает, потому что оба списка уже отсортированы.

4. **Сложность** — O(n + m) по времени, где n и m — длины списков. Мы проходим
   по каждому узлу ровно один раз.

## Альтернатива: рекурсия

Задачу можно решить и рекурсивно:

```kotlin
fun mergeTwoLists(l1: ListNode?, l2: ListNode?): ListNode? = when {
    l1 == null -> l2
    l2 == null -> l1
    l1.`val` < l2.`val` -> {
        l1.next = mergeTwoLists(l1.next, l2)
        l1
    }
    else -> {
        l2.next = mergeTwoLists(l1, l2.next)
        l2
    }
}
```

Это коротко и элегантно, но для больших списков может вызвать переполнение
стека (рекурсия O(n+m) глубины). В задачах LeetCode это обычно проходит, но *
*итеративный метод с dummy считается более надёжным** и универсальным.

## Как подходить к подобным задачам в будущем?

- Всегда спрашивайте себя: **«Могу ли я использовать dummy node?»** — если да,
  то делайте.
- Определите, какие указатели вам нужны: для обхода исходных списков и для
  построения результата.
- Не бойтесь использовать `?.` и `?:` в Kotlin — они упрощают работу с
  nullable-ссылками.
- И помните: слияние двух отсортированных списков — это база для более сложных
  задач, например, **объединения K списков** или **разбиения списка вокруг
  заданного значения**.
