# 203. Remove Linked List Elements

## Условие

Имея в качестве начального узла связанный список и целое число val, удалите все
узлы связанного списка, у которых Node.val == val, и верните новый начальный
узел.

Example 1:

![ex_203.jpg](../../../../../imgs/ex_203.jpg)

Input: head = [1,2,6,3,4,5,6], val = 6
Output: [1,2,3,4,5]

Example 2:

Input: head = [], val = 1
Output: []

Example 3:

Input: head = [7,7,7,7], val = 7
Output: []

Constraints:

The number of nodes in the list is in the range [0, 10^4].
1 <= Node.val <= 50
0 <= val <= 50

## Решение

Отлично, задача **203. Remove Linked List Elements** — это идеальный пример для
отработки техники **фиктивного узла (dummy node)**, потому что здесь голова
списка может быть удалена. Мы должны удалить все узлы, значение которых равно
заданному `val`.

---

## Методика: «Фиктивный узел и два указателя»

В этой задаче мы не знаем, будет ли удалён первый узел. Вместо того чтобы писать
отдельную логику для головы, мы создаём **dummy-узел**, который указывает на
`head`, и работаем с ним. Это позволяет единообразно обрабатывать все узлы.

Алгоритм:

1. Создаём `dummy` с произвольным значением (например, `-1`), его `next`
   указывает на `head`.
2. Заводим указатель `prev`, который будет указывать на предыдущий узел перед
   текущим (изначально `prev = dummy`).
3. Заводим указатель `curr`, который будет проходить по списку (изначально
   `curr = head`).
4. Пока `curr != null`:
    - Если `curr.val == val`, то пропускаем текущий узел:
      `prev.next = curr.next`. (Ссылка на `curr` теряется, он будет собран
      сборщиком мусора.)
    - Иначе просто сдвигаем `prev` на `curr`.
    - В любом случае `curr` сдвигаем на `curr.next`.
5. Возвращаем `dummy.next` (новая голова).

**Важно:** порядок обновления указателей. Если мы удаляем `curr`, то `prev` не
сдвигается (он остаётся на предыдущем узле, потому что мы перекинули ссылку).
Если не удаляем — сдвигаем `prev` на `curr`.

---

## Решение на Kotlin

```kotlin
fun removeElements(head: ListNode?, `val`: Int): ListNode? {
    val dummy = ListNode(-1)
    dummy.next = head
    var prev: ListNode? = dummy
    var curr = head

    while (curr != null) {
        if (curr.`val` == `val`) {
            // Удаляем curr: пропускаем его
            prev?.next = curr.next
        } else {
            // Не удаляем, двигаем prev
            prev = curr
        }
        // В любом случае двигаем curr
        curr = curr.next
    }

    return dummy.next
}
```

### Разбор кода

- **dummy** помогает обрабатывать случай удаления головы. Без него пришлось бы
  писать `if (head?.val == val)` и т.д.
- **prev** всегда указывает на последний узел, который не был удалён (или на
  `dummy` в начале).
- Когда мы удаляем `curr`, мы не перемещаем `prev`, потому что новый `curr` (
  который станет на следующей итерации) уже будет следующим за `prev`. Если бы
  мы сдвинули `prev`, мы бы потеряли связь.
- Когда `curr` сохраняется, мы сдвигаем `prev` на него.
- **Важно:** не забываем сдвигать `curr` на `curr.next` в конце каждой итерации,
  даже если удалили.

## Альтернативный подход (без dummy, с проверкой головы)

Можно обойтись без dummy, но тогда придётся отдельно обрабатывать удаление
головы в цикле while:

```kotlin
fun removeElements(head: ListNode?, `val`: Int): ListNode? {
    var head = head
    // Удаляем все головы, которые равны val
    while (head != null && head.`val` == `val`) {
        head = head.next
    }
    if (head == null) return null
    var curr = head
    while (curr?.next != null) {
        if (curr.next?.`val` == `val`) {
            curr.next = curr.next?.next
        } else {
            curr = curr.next
        }
    }
    return head
}
```

Это работает, но код становится менее симметричным. Поэтому **dummy —
предпочтительный способ**.

---

## Сложность

- Время: O(n) — проходим по списку один раз.
- Память: O(1) — используем только несколько указателей.

---

## Частые ошибки

1. **Забыть сдвинуть `curr`** после удаления. Если вы напишете
   `curr = curr.next` только в `else`, то при удалении `curr` останется на том
   же месте, и вы зациклитесь. Поэтому `curr` нужно двигать всегда, независимо
   от удаления.
2. **Не обновлять `prev` правильно.** При удалении `prev` остаётся на месте; при
   сохранении — сдвигается.
3. **Использование `val` как имя параметра** (оно зарезервировано в Kotlin). В
   коде я пишу обратные кавычки, чтобы экранировать: `` `val` ``.
