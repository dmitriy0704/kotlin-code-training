# 142. Linked List Cycle II

## Условие

Получив начало с вязанного списка, верните узел, с которого начинается цикл.
Если
цикла нет, верните null.

Цикл в связанном списке возникает, если в списке есть узел, до которого можно
снова добраться, непрерывно следуя указателю next.

Внутри системы переменная pos используется для обозначения индекса узла, к
которому подключен указатель next указателя tail (индексация начинается с 0).
Она равна -1, если цикла нет. Обратите внимание, что pos не передается в
качестве параметра.

Не изменяйте связанный список.

Example 1:

![ex_142.png](../../../../../imgs/ex_142.png)

Input: head = [3,2,0,-4], pos = 1
Output: tail connects to node index 1
Explanation: There is a cycle in the linked list, where tail connects to the
second node.

Example 2:

Input: head = [1,2], pos = 0
Output: tail connects to node index 0
Explanation: There is a cycle in the linked list, where tail connects to the
first node.

Example 3:

Input: head = [1], pos = -1
Output: no cycle
Explanation: There is no cycle in the linked list.

Constraints:

Количество узлов в списке находится в диапазоне [0, 104].
-105 <= Node.val <= 105
pos is -1 or a valid index in the linked-list.

Дополнительный вопрос: Можно ли решить эту задачу, используя память со
сложностью O(1) (т.е. с постоянным объемом памяти)?

## Решение

Задача **142. Linked List Cycle II** — это логическое продолжение 141. Здесь
нужно не просто сказать, есть ли цикл, а **найти узел, с которого цикл
начинается** (то есть первый узел, в который можно попасть дважды, двигаясь по
`next`). Если цикла нет — вернуть `null`.

Здесь используется **расширенный алгоритм Флойда**, который состоит из двух фаз:

1. **Обнаружение встречи** (как в 141).
2. **Поиск входа в цикл** — после встречи один указатель ставится в начало
   списка, и оба начинают двигаться по одному шагу. Точка их новой встречи и
   есть начало цикла.

---

## Интуитивное объяснение второй фазы

Пусть:

- Расстояние от головы до начала цикла = `A`.
- Расстояние от начала цикла до точки встречи (по направлению движения) = `B`.
- Длина цикла = `C`.

В момент первой встречи (по алгоритму Флойда):

- `slow` прошёл `A + B` шагов.
- `fast` прошёл `A + B + k*C` шагов (где `k` — количество полных кругов,
  сделанных быстрым, пока медленный шёл до встречи).
- Так как `fast` двигался в два раза быстрее, его путь в два раза больше пути
  `slow`:  
  `2*(A + B) = A + B + k*C` → `A + B = k*C` → `A = k*C - B`.

Это означает, что если теперь запустить один указатель из головы, а другой из
точки встречи, и двигать их с одинаковой скоростью (по одному шагу), то они
встретятся ровно в начале цикла. Почему? Потому что указатель из головы пройдёт
расстояние `A` до входа; указатель из точки встречи за то же время пройдёт `A`
шагов, что эквивалентно `k*C - B`, то есть он сделает `k` полных кругов минус
`B` шагов, что как раз приведёт его к началу цикла.

## Решение на Kotlin

```kotlin
fun detectCycle(head: ListNode?): ListNode? {
    var slow = head
    var fast = head

    // Фаза 1: поиск встречи
    while (fast != null && fast.next != null) {
        slow = slow?.next
        fast = fast.next?.next
        if (slow == fast) {
            // Фаза 2: поиск входа в цикл
            var ptr1 = head
            var ptr2 = slow
            while (ptr1 != ptr2) {
                ptr1 = ptr1?.next
                ptr2 = ptr2?.next
            }
            return ptr1
        }
    }
    return null // цикла нет
}
```

### Разбор кода

- **Фаза 1** полностью повторяет решение 141: двигаем `slow` на 1 шаг, `fast` на
  2, пока не встретятся или не достигнут конца.
- При встрече (если цикл есть) начинается **фаза 2**:
    - `ptr1` ставим в `head` (начало списка).
    - `ptr2` оставляем в точке встречи (`slow` или `fast` — они равны).
    - Двигаем оба на один шаг за итерацию, пока они не укажут на один узел.
- Этот узел и есть вход в цикл. Возвращаем его.
- Если цикл отсутствует, возвращаем `null`.

### Проверка на пустой список и список без цикла

- Если `head` пуст, то `slow` и `fast` оба `null`, цикл не запускается,
  возвращается `null`.
- Если список без цикла, то `fast` достигнет `null`, и функция вернёт `null`.

## Альтернативный подход с `HashSet`

Как и в 141, можно использовать множество для запоминания посещённых узлов.
Тогда первым узлом, который встретится повторно, будет вход в цикл.

```kotlin
fun detectCycle(head: ListNode?): ListNode? {
    val seen = mutableSetOf<ListNode>()
    var curr = head
    while (curr != null) {
        if (seen.contains(curr)) return curr
        seen.add(curr)
        curr = curr.next
    }
    return null
}
```

Это проще для понимания, но использует O(n) памяти. В интервью обычно ожидают
алгоритм Флойда с O(1) памяти.

---

## Частые ошибки

1. **Игнорирование null** в `fast.next?.next` — надо проверять
   `fast.next != null` перед доступом.
2. **Неправильное движение во второй фазе** — если двигать один указатель
   быстрее, то они никогда не встретятся так, как нужно.
3. **Забыть, что `slow` и `fast` после встречи могут указывать на один объект, и
   использовать его как `ptr2`** — это правильно, ведь они встретились в
   некоторой точке внутри цикла.
