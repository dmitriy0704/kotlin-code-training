# 19. Remove Nth Node From End of List

## Условие

Имея начало связанного списка, удалите n-й узел с конца списка и верните его
начало.

Example 1:

![ex_19.jpg](../../../../../imgs/ex_19.jpg)

Input: head = [1,2,3,4,5], n = 2
Output: [1,2,3,5]

Example 2:
Input: head = [1], n = 1
Output: []

Example 3:
Input: head = [1,2], n = 1
Output: [1]

Constraints:

The number of nodes in the list is sz.
1 <= sz <= 30
0 <= Node.val <= 100
1 <= n <= sz

## Решение

Отлично, задача **19. Remove Nth Node From End of List** — это классический
пример использования **двух указателей с фиксированным расстоянием**. Здесь
важно удалить узел за **один проход**, не зная заранее длину списка.

---

## Методика: «Два указателя (Fast & Slow) с дистанцией»

Мы используем два указателя:

- **`fast`** — уходит вперёд на `n` шагов.
- **`slow`** — стартует с той же точки.

Когда `fast` достигает конца списка (становится `null`), `slow` будет указывать
на узел, который находится **перед** удаляемым (ровно на расстоянии `n` от
конца). Затем мы просто перекидываем ссылку `slow.next = slow.next.next`.

**Важная деталь:** Чтобы правильно удалить голову (когда удаляем первый узел),
используем **фиктивный узел `dummy`**. Это избавляет от отдельных проверок.

---

## Алгоритм по шагам

1. Создаём `dummy` с произвольным значением (например, `0`) и его `next`
   указывает на `head`.
2. Инициализируем `slow = dummy` и `fast = dummy`.
3. Сдвигаем `fast` на `n + 1` шаг вперёд. Теперь между `slow` и `fast` ровно `n`
   узлов.
4. Двигаем оба указателя по одному шагу, пока `fast` не станет `null`. Когда
   `fast` достигнет конца, `slow` будет указывать на узел **перед** удаляемым.
5. Удаляем узел: `slow.next = slow.next.next`.
6. Возвращаем `dummy.next` (новая голова).

**Почему `n + 1`?**  
Если `fast` сдвинуть на `n+1`, то расстояние между `slow` и `fast` будет `n`
узлов. Когда `fast` станет `null`, `slow` будет указывать на предыдущий узел
перед удаляемым. Если бы мы сдвинули на `n`, то при достижении `fast` конца
`slow` указывал бы на сам удаляемый узел, и удалить его было бы сложнее.

---

## Решение на Kotlin

```kotlin
fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
    val dummy = ListNode(0)    // фиктивный узел
    dummy.next = head
    var slow: ListNode? = dummy
    var fast: ListNode? = dummy

    // Сдвигаем fast на n+1 шагов вперёд
    repeat(n + 1) {
        fast = fast?.next
    }

    // Двигаем оба, пока fast не дойдёт до конца
    while (fast != null) {
        slow = slow?.next
        fast = fast.next
    }

    // slow.next — это удаляемый узел
    slow?.next = slow?.next?.next

    return dummy.next
}
```

---

## Альтернативное решение (без dummy, но с проверкой головы)

Можно обойтись без dummy, но тогда надо обрабатывать случай удаления головы
отдельно:

```kotlin
fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
    var fast = head
    repeat(n) { fast = fast?.next }

    // Если fast == null, значит, удаляем голову
    if (fast == null) return head?.next

    var slow = head
    while (fast?.next != null) {
        slow = slow?.next
        fast = fast.next
    }
    // slow.next — удаляемый узел
    slow?.next = slow?.next?.next
    return head
}
```

Но первый вариант с `dummy` более надёжен и универсален.

## Сложность

- Время: O(n) — один проход списка.
- Память: O(1) — только несколько указателей.

---

## Частые ошибки

1. **Не сдвинуть `fast` на `n+1`** (или не учесть dummy). Если использовать `n`
   вместо `n+1`, то `slow` будет указывать на удаляемый узел, а не на
   предыдущий, и удалить его будет сложнее.
2. **Пропустить проверку на null при сдвиге `fast`** в цикле `repeat(n+1)`. В
   корректных входных данных `n` всегда меньше длины списка, поэтому `fast` не
   станет `null` до завершения сдвига, но лучше быть осторожным.
3. **Не обновить указатели при удалении головы** (если использовать подход без
   dummy). Поэтому я рекомендую всегда использовать dummy в таких задачах.

### Когда голова меняется?

Голова меняется **только тогда**, когда удаляемый узел — **самый первый** (то
есть `head`). Это происходит, если `N` равно длине списка.

Например:

- Список: `1 -> 2 -> 3 -> 4 -> 5` (длина 5)
- Удаляем `5-й с конца` (то есть N = 5) — это узел со значением `1`.
- Результат должен быть: `2 -> 3 -> 4 -> 5`. Голова теперь `2`, а не `1`.

В вашем примере вы удаляли `4` (N = 2), и голова не изменилась. Но если бы N =
5, то голова бы изменилась.

---

### Почему `dummy` помогает?

Без `dummy` пришлось бы писать специальный код для случая удаления головы.
Например, в альтернативном решении (без dummy) мы делаем так:

```kotlin
fun removeNthFromEnd(head: ListNode?, n: Int): ListNode? {
    var fast = head
    repeat(n) { fast = fast?.next }
    if (fast == null) {
        // Удаляем голову
        return head?.next
    }
    // ... дальше обычное удаление
}
```

То есть мы вынуждены проверять, не равен ли `fast` `null` после сдвига на `n`
шагов. Если равен — значит, мы сдвинулись за пределы списка, и удаляемый узел —
это голова.

С `dummy` эта проверка не нужна, потому что мы всегда работаем с предыдущим
узлом. Даже если удаляется голова, `dummy.next` просто станет указывать на
второй узел.

---

### Как работает `dummy` в задаче 19

Рассмотрим случай `N = 5` для списка длиной 5:

1. `dummy -> 1 -> 2 -> 3 -> 4 -> 5`
2. `slow = dummy`, `fast = dummy`
3. Сдвигаем `fast` на `N+1 = 6` шагов. Так как в списке всего 6 узлов (с dummy),
   `fast` станет `null` ровно после прохождения всех узлов.
4. Теперь двигаем `slow` и `fast` по одному шагу, пока `fast != null`. Но `fast`
   уже `null`, поэтому цикл не выполнится ни разу. `slow` так и останется на
   `dummy`.
5. Удаляем `slow.next` — это `head` (узел `1`). Теперь `dummy.next` указывает на
   `2`.
6. Возвращаем `dummy.next` — новая голова `2`.

Видите? Мы даже не писали отдельного условия для удаления головы. `dummy` просто
«сидит» перед списком, и удаление всегда происходит через `slow.next`, где
`slow` — это предыдущий узел перед удаляемым. В случае удаления головы
предыдущим узлом оказывается сам `dummy`.

---

### Итог

- В большинстве случаев (когда удаляем не голову) голова не меняется.
- Но если удаляется первый узел, голова меняется, и `dummy` помогает обработать
  этот случай без лишних `if`.
- Поэтому мы всегда используем `dummy` для единообразия — код становится проще и
  надёжнее.
