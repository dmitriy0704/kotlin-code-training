# Алгоритм поиска цикла Флойда.

### Суть:

Алгоритм поиска цикла Флойда (также известный как «алгоритм черепахи и зайца») —
это эффективный метод поиска циклов в связных списках или последовательностях.
Его суть заключается в использовании двух указателей, которые двигаются по
структуре данных с разной скоростью.

## Принцип работы

* Черепаха (медленный указатель): смещается вперед на 1 узел за один шаг.
* Заяц (быстрый указатель): смещается вперед на 2 узла за один шаг.

Если в структуре данных нет цикла, быстрый указатель (заяц) первым дойдет до
конца списка (NULL), и алгоритм завершится.
Если в структуре есть цикл, то заяц обязательно догонит черепаху внутри цикла.
Их встреча в одной точке — главное доказательство наличия цикла.

## Зачем он нужен?

1. Определение наличия цикла: быстро узнать, зациклен ли список.
2. Поиск точки начала цикла: после встречи указателей можно точно определить
   узел, где цикл начинается.
3. Определение длины цикла: подсчет шагов от момента встречи до возвращения в ту
   же точку.

## Главные преимущества

* Экономия памяти: алгоритм использует всего две переменные для указателей.
  Сложность по памяти — O(1).
* Высокая скорость: в худшем случае алгоритм находит цикл за линейное время.
  Сложность по времени — O(N).
* Чистота данных: не нужно модифицировать узлы списка или добавлять к ним флаги
  посещения.

# На примере массива [3,2,0,-4], как вообще это определяется визуально

Визуально эту задачу проще всего представить как настольную игру-ходилку или бег
по треку.
Массив [3, 2, 0, -4] в условиях задачи — это значения узлов. Но самое важное —
это связи между ними. По условию LeetCode, последний узел -4 подключается
обратно к узлу со значением 2 (индекс 1).

## 🗺️ Визуальная карта списка (петля)

[3] ---> [2] ---> [0] ---> [-4]
^ |

          |_________________|

Узел 2 становится входом в кольцо. Элементы 2 -> 0 -> -4 -> 2 зациклены.
------------------------------

## 🏃 Пошаговая визуализация «Зайца» и «Черепахи»

Давай пошагово передвигать маркеры S (Slow / Черепаха, +1 шаг) и F (Fast / Заяц,
+2 шага). Оба стартуют с первого узла 3.

## Старт (Шаг 0)

Оба стоят на первом элементе.

* S стоит на [3]
* F стоит на [3]

## Шаг 1

* Черепаха (S) делает 1 шаг вперед: переходит с [3] на [2].
* Заяц (F) делает сразу 2 шага вперед: с [3] перепрыгивает через [2] и встает
  на [0].

```text
[3] ---> [2] ---> [0] ---> [-4]
          ^        ^        |
          |        |        |
          S        F________|

```

## Шаг 2

* Черепаха (S) делает 1 шаг: переходит с [2] на [0].
* Заяц (F) делает 2 шага: с [0] идет на [-4], а оттуда по стрелке возвращается
  назад на [2].

```text
[3] ---> [2] ---> [0] ---> [-4]
          ^        ^        |
          |        |        |
          F        S________|
```

Заметь: они поменялись местами. Заяц теперь позади Черепахи внутри кольца.

## Шаг 3

* Черепаха (S) делает 1 шаг: переходит с [0] на [-4].
* Заяц (F) делает 2 шага: с [2] идет на [0], а затем на [-4].

```text
[3] ---> [2] ---> [0] ---> [-4]
          ^                 ^
          |                 |
          |_________________S, F

```

Они встретились! Оба указателя теперь смотрят на узел [-4]. Код видит условие
slow == fast, останавливает цикл и выдает true (цикл есть).

Если бы цикла не было, стрелка от [-4] вела бы в пустоту (null). Тогда на Шаге 2
Заяц мгновенно бы уперся в тупик, и игра завершилась бы результатом false.

# Что за логика перепрыгивания с -4 на 2?

Ты задал отличный вопрос! В реальном мире из массива [3, 2, 0, -4] невозможно
автоматически понять, что -4 соединяется с 2. Массив сам по себе не имеет
никаких циклов.
Вводная строка вроде head = [3,2,0,-4], pos = 1, которую ты видишь в условии на
LeetCode — это просто способ, которым сайт описывает тебе тест.
Вот как это устроено изнутри:

## 1. Это особенность структуры данных (Linked List)

В отличие от обычного массива, где элементы лежат в памяти строго друг за
другом, в Связном Списке (Linked List) каждый элемент — это отдельный
независимый объект (узел/Node).
У него есть два поля:

* val — само значение (например, 3).
* next — ссылка (указатель) на любой другой объект в памяти.

Куда указывает стрелка next — решает программист, который этот список создает.
Она может указывать на следующий элемент, может указывать на null (конец
списка), а может указывать на любой из предыдущих элементов.

## 2. Зачем LeetCode пишет pos = 1?

Параметр pos (позиция) нужен только для визуализации теста на сайте.

* На LeetCode под капотом работает скрытый код.
* Он берет массив [3, 2, 0, -4] и превращает его в узлы.
* Видя pos = 1, этот код берет next последнего узла (-4) и вручную привязывает
  его к узлу с индексом 1 (то есть к 2).

## 3. Что видит твой код?

Твой код на Kotlin не видит массив и не видит переменную pos. В твою функцию
hasCycle(head: ListNode?) приходит только один самый первый узел — 3.
Твой алгоритм начинает идти вслепую по стрелкам next:

1. Из узла 3 по стрелке next переходит в 2.
2. Из узла 2 переходит в 0.
3. Из узла 0 переходит в -4.
4. Из узла -4 по стрелке next (которую скрытно настроил LeetCode) внезапно снова
   попадает в 2.

Твой код не знает заранее, будет там цикл или нет. Он просто идет по ссылкам,
как по канату. Если канат завязан в кольцо — «Заяц» и «Черепаха» встретятся.
Если канат оборвется (next == null) — цикла нет.

# Ручное создание такого цикла на Kotlin, чтобы потестировать его локально?

Вот как можно воссоздать эту ситуацию локально в IntelliJ IDEA или любом
онлайн-компиляторе Kotlin (например, play.kotlinlang.org).
Мы вручную создадим четыре узла и свяжем их «стрелочками» next так, чтобы
получился цикл, как в тесте LeetCode.

## Полный код для запуска

Вы можете скопировать этот код целиком и запустить его:

```kotlin
// 1. Определение структуры узла (как на LeetCode)
class ListNode(var `val`: Int) {
    var next: ListNode? = null
}

// 2. Класс с нашим решением
class Solution {
    fun hasCycle(head: ListNode?): Boolean {
        if (head == null || head.next == null) return false

        var slow = head
        var fast = head

        while (fast != null && fast.next != null) {
            slow = slow?.next
            fast = fast.next?.next

            if (slow == fast) return true
        }
        return false
    }

}

// 3. Функция main для ручной сборки списка и тестирования

fun main() {
// Шаг А: Создаем изолированные узлы в памяти (пока без связей)
    val node3 = ListNode(3)
    val node2 = ListNode(2)
    val node0 = ListNode(0)
    val nodeMinus4 = ListNode(-4)

    // Шаг Б: Связываем их последовательно друг за другом
    node3.next = node2        // 3 -> 2
    node2.next = node0        // 2 -> 0
    node0.next = nodeMinus4   // 0 -> -4

    // Сейчас список выглядит так: 3 -> 2 -> 0 -> -4 -> null (Цикла нет!)

    // Шаг В: Замыкаем цикл вручную (моделируем pos = 1)
    // Направляем стрелку от последнего узла обратно к узлу со значением 2
    nodeMinus4.next = node2

    // Теперь список зациклен: 3 -> 2 -> 0 -> -4 -> 2 -> 0 ...

    // Шаг Г: Передаем ГОВУ (node3) в наше решение
    val solution = Solution()
    val result = solution.hasCycle(node3)

    // Выводим результат в консоль
    println("Есть ли в списке цикл? Ответ: $result")

}
```

## 💡 Что здесь произошло?

1. В блоке Шаг А мы просто выделили память под 4 отдельные коробки с числами.
   Они никак не знали друг о друге.
2. В блоке Шаг Б мы проложили между ними рельсы. Если бы мы остановились тут, то
   solution.hasCycle(node3) вернул бы false.
3. В блоке Шаг В мы перенаправили выход из последней коробки (nodeMinus4.next)
   не в пустоту (null), а в node2. Именно это действие превратило обычную
   цепочку в бесконечный аттракцион.

# Что такое ListNode

Нет, ListNode в LeetCode — это не LinkedList из Java. Это гораздо более простая,
«низкоуровневая» структура.
Вот в чем ключевая разница:

## 1. Java-класс LinkedList — это «умный менеджер»

Стандартный java.util.LinkedList — это полноценный, сложный класс-контейнер.

* Вы не управляете его внутренними стрелками напрямую.
* Вы просто вызываете методы .add(), .remove(), .get(index).
* Внутри себя он скрывает узлы, автоматически связывает их и гарантирует, что в
  нем никогда не появится цикл. Вы технически не сможете зациклить стандартный
  Java LinkedList через его публичные методы.

## 2. LeetCode-класс ListNode — это «голый узел»

ListNode — это простейший строительный блок (кирпичик), из которого связный
список строится вручную.
На LeetCode он всегда объявлен примерно так:

class ListNode(var `val`: Int) {
var next: ListNode? = null
}

Здесь нет никаких методов для добавления или удаления элементов. У вас есть
только число и прямая ссылка на следующий такой же кирпичик.
Из-за того, что программист имеет полный и прямой доступ к свойству next, он
может направить эту стрелку куда угодно — в том числе и назад, устроив
бесконечный цикл.

## 💡 Аналогия для понимания:

* ListNode — это один конкретный вагон поезда. Чтобы собрать состав, вам нужно
  вручную прицепить крюк (next) первого вагона к следующему вагону. Если вы
  прицепите крюк последнего вагона к середине поезда, получится замкнутый круг.
* Java LinkedList — это весь поезд целиком, которым управляет автоматика. Вы
  просто говорите: «Добавь пассажирский вагон в хвост», и автоматика сама делает
  всю работу, не позволяя вагонам запутаться.

В задачах на алгоритмы (вроде LeetCode) почти всегда используют именно ListNode,
чтобы проверить, умеете ли вы работать с памятью и указателями «вручную», без
готовых библиотек.
