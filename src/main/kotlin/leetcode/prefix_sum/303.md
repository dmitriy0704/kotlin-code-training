# 303. Range Sum Query - Immutable

# Условие

Имея целочисленный массив nums, обработайте несколько запросов следующего типа:

Вычислите сумму элементов массива nums в диапазоне индексов от left до right
включительно, где left <= right.

Реализуйте класс NumArray:

- NumArray(int[] nums) Инициализирует объект массивом целых чисел nums.
- Функция `int sumRange(int left, int right)` возвращает сумму элементов массива
  `nums` в диапазоне от индексов `left` до `right` включительно (т. е.
  nums[left] + nums[left + 1] + ... + nums[right]).

Example 1:

Input
["NumArray", "sumRange", "sumRange", "sumRange"]
[[[-2, 0, 3, -5, 2, -1]], [0, 2], [2, 5], [0, 5]]
Output
[null, 1, -1, -3]

Explanation
NumArray numArray = new NumArray([-2, 0, 3, -5, 2, -1]);
numArray.sumRange(0, 2); // return (-2) + 0 + 3 = 1
numArray.sumRange(2, 5); // return 3 + (-5) + 2 + (-1) = -1
numArray.sumRange(0, 5); // return (-2) + 0 + 3 + (-5) + 2 + (-1) = -3

# Решение

Задача LeetCode 303 (Range Sum Query - Immutable) — это классическая задача на
алгоритм префиксных сумм (Prefix Sum). Она идеально продолжает логику предыдущей
задачи 1480, но выводит её на новый уровень. [1, 2]
В этой задаче от нас требуют создать класс, который умеет мгновенно выдавать
сумму элементов массива на любом отрезке от left до right включительно. При этом
метод sumRange будет вызываться огромное количество раз (до $10^4$ раз). [2]

## ❌ Почему не сработает обычный цикл (Brute Force)?

Если каждый раз при вызове sumRange(left, right) запускать цикл for от left до
right и складывать числа, такое решение получит ошибку TLE (Time Limit
Exceeded).
Каждый запрос в худшем случае будет выполняться за $O(N)$. Умножаем на $10^4$
вызовов — алгоритм становится слишком медленным. [2, 3]

## Суть оптимального решения

Мы должны один раз в конструкторе класса потратить время O(N) и построить
массив префиксных сумм, чтобы затем отвечать на абсолютно любой запрос sumRange
ровно за одно действие O(1) без каких-либо циклов.
Чтобы избежать постоянных проверок «а не равен ли left нулю?», массив префиксных
сумм (prefix) делают размером N + 1, где самый первый элемент равен 0. 
Формула для поиска суммы от left до right:
sumRange(left, right) = prefix[right + 1] - prefix}[left]


## Визуальный пример

Пусть исходный массив: nums = [3, 5, 2, -2].
Мы создаем массив prefix размером на 1 больше и заполняем его накопительным
итогом: [2, 4]

Индексы:      0 1 2 3 4
+----+----+----+----+----+
prefix = | 0 | 3 | 8 | 10 | 8 |
+----+----+----+----+----+
\ \ \    \
3 3+5 8+2 10+(-2)

Задача: Найти сумму элементов от индекса 1 до 3 включительно (то есть 5 + 2 + (
-2) = 5).
Решение по формуле: prefix[3 + 1] - prefix[1] $\rightarrow$ prefix[4] -
prefix[1] $\rightarrow$ 8 - 3 = 5. [4]
Мы просто взяли сумму всего массива до конца отрезка и «отрезали» от неё лишний
левый кусок.
------------------------------

## Код решения на Kotlin

Вот чистое и эффективное решение: [4]

```kotlin
class NumArray(nums: IntArray) {

    // Создаем массив префиксных сумм на 1 элемент больше исходного
    private val prefix = IntArray(nums.size + 1)

    init {
        // Заполняем массив кумулятивной суммой
        for (i in nums.indices) {
            prefix[i + 1] = prefix[i] + nums[i]
        }
    }

    fun sumRange(left: int, right: Int): Int {
        // Возвращаем результат за O(1) с помощью простого вычитания
        return prefix[right + 1] - prefix[left]
    }

}
```



## Сложность алгоритма:

* Инициализация (Конструктор): $O(N)$ по времени и $O(N)$ по памяти (создаем
  массив prefix).
* Вызов sumRange: $O(1)$ по времени и $O(1)$ по памяти (всего одна операция
  вычитания). Намного быстрее исходного решения. [2, 5, 6]
