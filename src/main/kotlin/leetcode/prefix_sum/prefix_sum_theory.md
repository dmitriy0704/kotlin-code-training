# Теория о алгоритме "Prefix Sum"

Простыми словами, **префиксная сумма** — это массив, в котором каждый элемент
хранит сумму всех элементов исходного массива от начала до текущей позиции
включительно. Это мощный приём для предобработки данных, который позволяет
получать сумму элементов на любом подотрезке за мгновение (за O(1)), а не за
долгий проход по массиву (за O(n)).

Давай разберем все по порядку, с акцентом на Kotlin.

### 🧠 Как это работает? Основная логика

Представь, что у нас есть исходный массив `arr`. Мы строим новый массив
`prefixSum` такой, что **`prefixSum[i] = arr[0] + arr[1] + ... + arr[i]`**.

* **Как построить:** Это делается за один проход по массиву (`O(n)`), накапливая
  сумму в переменной и записывая её в массив префиксных сумм.

* **Как получить сумму любого подмассива от `left` до `right`:** Есть простая
  формула, которая и дает главное преимущество — ответ за `O(1)`:
    * **Sum(left, right) = prefixSum[right] - (prefixSum[left - 1])**
    * Если `left` == 0, то сумма от начала массива равна просто
      `prefixSum[right]`.

Визуализируем на примере `arr = [2, 4, 1, 5, 3]`:

| Индекс | Исходный массив | Префиксная сумма | Сумма от `left` до `right`                                                                      |
|:-------|:----------------|:-----------------|:------------------------------------------------------------------------------------------------|
| 0      | 2               | 2                | `arr[0] + arr[3]` = 2 + 4 + 1 + 5 = 12<br>**Формула:** `prefix[3]` - `prefix[-1]` = 12 - 0 = 12 |
| 1      | 4               | 2 + 4 = 6        | `arr[1] + arr[3]` = 4 + 1 + 5 = 10<br>**Формула:** `prefix[3]` - `prefix[0]` = 12 - 2 = 10      |
| 2      | 1               | 6 + 1 = 7        | `arr[2] + arr[3]` = 1 + 5 = 6<br>**Формула:** `prefix[3]` - `prefix[1]` = 12 - 6 = 6            |
| 3      | 5               | 7 + 5 = 12       | `arr[3]` = 5<br>**Формула:** `prefix[3]` - `prefix[2]` = 12 - 7 = 5                             |
| 4      | 3               | 12 + 3 = 15      | -                                                                                               |

### 💻 Kotlin в деле: Примеры кода

Теперь, когда мы знаем теорию, посмотрим на реализацию.

#### Пример 1: Базовый одномерный массив

Классическое решение задачи **LeetCode 303. Range Sum Query - Immutable**.
В конструкторе мы принимаем массив и строим префиксные суммы в массиве
`prefixSums` размером `n + 1`. Такой подход с дополнительной ячейкой в начале
значительно упрощает формулу, избавляя от необходимости проверять `left == 0`.

```kotlin
class NumArray(nums: IntArray) {
    // Создаем массив префиксных сумм на 1 длиннее, чтобы избежать проверок границ.
    // prefixSums[0] будет всегда равен 0.
    private val prefixSums = IntArray(nums.size + 1)

    init {
        var sum = 0
        // Заполняем массив, начиная с индекса 1, потому что prefixSums[0] = 0.
        for (i in nums.indices) {
            sum += nums[i]
            prefixSums[i + 1] = sum
        }
    }

    fun sumRange(left: Int, right: Int): Int {
        // Теперь сумма от left до right включительно — это разность двух префиксов.
        // Префикс для right+1 включает в себя nums[right], а префикс для left — nums[left-1].
        return prefixSums[right + 1] - prefixSums[left]
    }
}
```

Код очень эффективен: построение занимает O(n), а каждый запрос `sumRange` — O(
1).

#### Пример 2: Сложная техника с HashMap (LeetCode 560)

Это более сложная и частая задача. Нужно найти количество подмассивов, сумма
которых равна `k`. Магия здесь в том, что если мы знаем текущую префиксную сумму
`currentSum`, то нам нужно найти, сколько раз ранее встречалась префиксная сумма
`currentSum - k`. Это количество и будет количеством подмассивов,
заканчивающихся на текущем элементе.

```kotlin
fun subarraySum(nums: IntArray, k: Int): Int {
    // Храним частоту появления префиксных сумм.
    // Ключ: префиксная сумма, Значение: сколько раз она встречалась.
    val prefixSumCount = mutableMapOf<Int, Int>()
    // Инициализируем карту. Это важно для случая, когда сам подмассив с начала до i дает сумму k.
    prefixSumCount[0] = 1

    var count = 0
    var currentSum = 0

    for (num in nums) {
        currentSum += num

        // Проверяем, существует ли уже префиксная сумма, которая в паре с currentSum дает k.
        // Если да, то прибавляем количество таких случаев.
        count += prefixSumCount.getOrDefault(currentSum - k, 0)

        // Сохраняем текущую префиксную сумму для будущих итераций.
        prefixSumCount[currentSum] =
            prefixSumCount.getOrDefault(currentSum, 0) + 1
    }
    return count
}
```

Сложность этого решения — O(n) по времени и O(n) по памяти, что огромный
прогресс по сравнению с O(n²) для наивного подхода.

### 🔍 Когда использовать префиксные суммы?

Главные индикаторы — это слова в задаче и форма данных:

* **Множественные запросы**: "Ответь на много запросов о сумме на отрезке", "Для
  каждого `i` найди сумму от `i` до `j`".
* **Подмассивы**: "Найди подмассив с максимальной/минимальной суммой", "Найди
  количество подмассивов, сумма которых равна X".
* **Работа с диапазонами**: "Сколько элементов в диапазоне `[L, R]`
  удовлетворяют условию?"
* **Условия на накопление**: Если задачу можно переформулировать с
  использованием разницы накопленных сумм.

### 📝 Ключевые нюансы и частые ошибки

* **Начальная инициализация карты**: В `subarraySum` помни про
  `prefixSumCount[0] = 1`. Если её не добавить, решение не будет учитывать
  подмассивы, которые начинаются с индекса 0.
* **Индексы в формуле**: При реализации будь внимателен, особенно если размер
  `prefixSums` = `n+1`. Сумма для `[left, right]` — это
  `prefixSums[right+1] - prefixSums[left]`.
* **Тип данных**: Для больших массивов и сумм используй `LongArray` и `Long`,
  чтобы избежать переполнения `Int`.
* **Отрицательные числа**: Техника `Prefix Sum + HashMap` прекрасно работает и с
  ними! В отличие от скользящего окна, которое требует монотонности данных.

## Почему в примере сумма `2 + 4 + 1 + 5 = 12`?

В таблице я хотел показать вычисление суммы для **подмассива от `left`
до `right`** с разными индексами. В первой строке:

- **`left = 0`**, **`right = 3`** (хотя в ячейке написано `arr[0] + arr[3]`, это
  означает сумму элементов с индексами от 0 до 3 включительно).
- Исходный массив: `arr = [2, 4, 1, 5, 3]`.
- Элементы с индексами 0,1,2,3 — это `2, 4, 1, 5`. Их сумма действительно `12`.
- Элемент с индексом 4 (`3`) не входит в этот подмассив, потому что `right = 3`.

Запись `arr[0] + arr[3]` — это условное обозначение «от `arr[0]` до `arr[3]`
включительно», а не арифметическая сумма двух чисел. Возможно, следовало бы
написать `arr[0..3]`. Извини за неоднозначность.

## Что насчёт `prefix[-1]`?

Формула `prefix[3] - prefix[-1]` — это математическая запись для случая
`left = 0`. Поскольку массив `prefix` определяется как
`prefix[i] = arr[0] + ... + arr[i]`, то:

- `prefix[3] = 2+4+1+5 = 12`.
- `prefix[-1]` — это условная «сумма до начала массива», которая равна `0`.

В реальном коде ты никогда не используешь индекс `-1`. Вместо этого либо
проверяешь `left == 0`, либо создаёшь массив `prefix` длиной `n+1`, где
`prefix[0] = 0`, и тогда сумма от `left` до `right` равна
`prefix[right+1] - prefix[left]`. Это стандартный безопасный приём.

## Итог: как правильно интерпретировать таблицу

| Индекс | Исходный массив | Префиксная сумма | Сумма от `left` до `right` (пример) |
|--------|-----------------|------------------|-------------------------------------|
| 0      | 2               | 2                | `left=0, right=3` → 2+4+1+5=12      |
| 1      | 4               | 6                | `left=1, right=3` → 4+1+5=10        |
| 2      | 1               | 7                | `left=2, right=3` → 1+5=6           |
| 3      | 5               | 12               | `left=3, right=3` → 5               |
| 4      | 3               | 15               | —                                   |

**Ключевой вывод:**  
`arr[4]` (значение 3) не входит в суммы примеров, потому что `right` нигде не
достигает 4. Таблица просто иллюстрирует формулу для разных `right`, но не
включает последний элемент.

## Что делать, чтобы не путаться?

Всегда чётко задавай границы подмассива. В коде на Kotlin лучше использовать *
*массив префиксных сумм размером `n+1`**:

```kotlin
val prefix = IntArray(nums.size + 1)
for (i in nums.indices) {
    prefix[i + 1] = prefix[i] + nums[i]
}
// Сумма nums[left]..nums[right] включительно:
val sum = prefix[right + 1] - prefix[left]
```

Тогда никаких `-1` и путаницы с индексами.
