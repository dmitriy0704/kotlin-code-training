# 209. Minimum Size Subarray Sum

## Условие

Дан массив положительных целых чисел nums и положительное целое число target.
Верните подмассив минимальной длины, сумма элементов которого больше или равна
target. Если такого подмассива не существует, верните 0.

Example 1:
Input: target = 7, nums = [2,3,1,2,4,3]
Output: 2
Explanation: The subarray [4,3] has the minimal length under the problem
constraint.

Example 2:
Input: target = 4, nums = [1,4,4]
Output: 1

Example 3:
Input: target = 11, nums = [1,1,1,1,1,1,1,1]
Output: 0

## Решение:

Суть задачи

Тебе даны:

- Массив из положительных чисел nums. Целевое число target.
- Нужно найти минимальную длину непрерывного подмассива (кусочка исходного
  массива), сумма элементов которого больше или равна target. Если такого
  подмассива нет, нужно вернуть 0.

Суть решения: Скользящее окно (Два указателя)

Решать задачу «в лоб» через перебор всех возможных кусочков (два цикла for) —
слишком медленно, это займет \(O(N^2)\) времени и на LeetCode упадет с ошибкой
Time Limit Exceeded.

Метод скользящего окна позволяет решить задачу за один проход (\(O(N)\)).

Представь себе гусеницу, которая ползет по массиву. У нее есть голова (правый
указатель right) и хвост (левый указатель left).

1. Голова (right) ползет вперед и поглощает числа, добавляя их к текущей сумме,
   пока сумма не станет хотя бы равна target.
2. Как только сумма стала нужной величины, мы фиксируем длину гусеницы.
3. Теперь хвост (left) начинает подтягиваться
   вперед (мы вычитаем числа из суммы), чтобы проверить: а не останется ли сумма
   всё еще достаточно большой, если мы уменьшим длину?
4. Повторяем это, пока голова не дойдет до конца массива.

## Код

```kotlin
import kotlin.math.min

class Solution {
    fun minSubArrayLen(target: Int, nums: IntArray): Int {
        var minLength = Int.MAX_VALUE // Инициализируем «бесконечностью»
        var currentSum = 0
        var left = 0 // Хвост нашего окна

        // Голова окна (right) идет вперед по массиву
        for (right in nums.indices) {
            currentSum += nums[right] // Добавляем элемент в окно

            // Пока сумма внутри окна подходит под условие, сужаем его слева
            while (currentSum >= target) {
                // Вычисляем текущую длину окна: (right - left + 1)
                minLength = min(minLength, right - left + 1)

                // Убираем левый элемент из суммы и двигаем хвост вперед
                currentSum -= nums[left]
                left++
            }
        }

        // Если minLength не изменился, значит подходящего подмассива нет, возвращаем 0
        return if (minLength == Int.MAX_VALUE) 0 else minLength
    }
}

```

## 🏃 Пошаговый разбор на примере: target = 7, nums = [2, 3, 1, 2, 4, 3]

Посмотрим, как двигаются наши указатели left (L) и right (R):

1. R встает на 2, затем на 3, затем на 1, затем на 2:
    * nums в окне: [2, 3, 1, 2]. currentSum = 8.
    * Ура, 8 >= 7. Длина окна: $3 - 0 + 1 = 4$. Записываем minLength = 4.
    * Сжимаем слева: вычитаем nums[0] (это 2). Сдвигаем L на индекс 1.
      currentSum становится 6.
    * Теперь 6 < 7. Цикл while завершен.
2. R идет дальше и встает на 4:
    * Окно сейчас: [3, 1, 2, 4]. currentSum = 10.
    * 10 >= 7. Длина окна: $4 - 1 + 1 = 4$. Наш минимум всё еще 4.
    * Сжимаем слева: вычитаем nums[1] (это 3). Сдвигаем L на индекс 2.
      currentSum становится 7.
    * Внутри while: проверяем условие 7 >= 7. Да! Новая длина окна [1, 2, 4]
      равна $4 - 2 + 1 = 3$. Обновляем: minLength = 3.
    * Сжимаем слева: вычитаем nums[2] (это 1). L сдвигается на индекс 3.
      currentSum становится 6. Выходим из while.
3. R встает на последний элемент 3:
    * Окно сейчас: [2, 4, 3]. currentSum = 9.
    * 9 >= 7. Длина окна $5 - 3 + 1 = 3$.
    * Сжимаем слева: вычитаем nums[3] (это 2). L сдвигается на индекс 4.
      currentSum становится 7.
    * Внутри while: 7 >= 7. Окно сократилось до [4, 3]. Его
      длина: $5 - 4 + 1 = 2$. Обновляем: minLength = 2.
    * Сжимаем слева: вычитаем nums[4] (это 4). L сдвигается на 5. currentSum
      становится 3.

Массив закончился. Ответ: 2 (это подмассив [4, 3]).

## Сложность алгоритма

* Времени: $O(N)$ — несмотря на то, что внутри for есть цикл while, каждый
  элемент массива посещается указателями left и right не более двух раз (один
  раз добавили в сумму, один раз вычли).
* Памяти: $O(1)$ — мы завели всего три числовые переменные.

`а можно в этой задаче отсортировать массив и просто складывать с конца?`

Короткий ответ — нет, в этой задаче так делать нельзя, и это разрушит
правильность решения.
Хотя идея кажется логичной (большие числа окажутся в конце, и мы быстрее наберем
нужную сумму), сортировка нарушает главное условие задачи.
Вот две причины, почему этот подход не сработает:

## 1. Нарушается условие «непрерывности» (Subarray)

В условии задачи четко сказано, что мы ищем subarray (подмассив). По
определению, подмассив — это непрерывная часть исходного массива. Элементы
должны идти строго друг за другом, как в оригинале.
Если мы отсортируем массив [2, 3, 1, 2, 4, 3], он превратится
в [1, 2, 2, 3, 3, 4].

* Если мы возьмем элементы с конца (4 и 3), их сумма равна 7. В отсортированном
  массиве они стоят рядом.
* Но в исходном массиве числа 4 и 3 тоже стоят рядом на конце (... 4, 3]),
  поэтому здесь ответ совпал.

А теперь посмотрим на другой пример, где этот трюк полностью ломается.

## 2. Пример, где сортировка дает неверный ответ

Пусть target = 7, а массив равен: [6, 1, 2, 1, 1]

* Правильное решение (без сортировки):
  Мы видим непрерывный кусочек [6, 1] в самом начале. Его сумма $6 + 1 = 7$.
  Длина этого подмассива равна 2. Это правильный ответ.
* Попытка с сортировкой:

    1. Сортируем массив: [1, 1, 1, 2, 6]
    2. Идем с конца: берем 6. Сумма 6, этого мало (нужно $\ge 7$).
    3. Берем следующее число с конца — 2. Сумма $6 + 2 = 8$. Условие выполнено!
    4. Мы взяли 2 элемента (6 и 2), длина вроде бы 2.
    5. Но посмотри на исходный массив [6, 1, 2, 1, 1]. Числа 6 и 2 в нем не
       стоят рядом! Между ними находится единица. Чтобы взять их в исходном
       массиве, нам пришлось бы захватить и единицу между ними: [6, 1, 2]. А
       длина такого подмассива уже равна 3, а не 2.

Таким образом, сортировка перемешивает элементы, и мы теряем информацию о том,
лежали ли эти числа рядом в изначальном списке.

## Важное различие в терминах LeetCode:

* Subarray (Подмассив) — элементы обязаны идти подряд, непрерывно. Сортировать
  нельзя.
* Subsequence (Подпоследовательность) — элементы можно брать из любых мест
  массива, главное сохранять их относительный порядок.
* Subset (Подмножество) — можно брать любые элементы в любом порядке. Вот здесь
  сортировка часто очень помогает!
