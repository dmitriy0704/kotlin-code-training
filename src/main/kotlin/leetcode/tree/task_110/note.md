# 110. Balanced Binary Tree

## Условие

Дано бинарное дерево. Определите, является ли оно сбалансированным по высоте.

Сбалансированное по высоте бинарное дерево — это бинарное дерево, в котором
глубина двух поддеревьев каждого узла никогда не отличается более чем на
единицу.

## Решение

Задача 110. Balanced Binary Tree (Сбалансированное бинарное дерево) — это
логическое развитие предыдущей задачи. Здесь нам нужно не просто посчитать
высоту, а использовать её для проверки важного свойства структуры данных.

## Суть задачи

Дерево считается сбалансированным по высоте, если для каждого его узла высота
левого и правого поддеревьев отличается не более чем на 1.
Посмотри на два примера:
Пример 1: Сбалансированное дерево (true)

```text
      3
     / \
    9  20
       / \
      15  7

```

* Для узла 20: левая высота 1 (15), правая 1 (7). Разница: 1 - 1 = 0 \le 1.
* Для корня 3: левая высота 1 (9), правая высота 2 (20 -> 15).
  Разница: 2 - 1 = 1 \le 1.
* Дерево сбалансировано.

Пример 2: Несбалансированное дерево (false)

```text
       1
      / \
     2   2
    / \
   3   3
  / \
 4   4

```

* На первый взгляд кажется, что у корня 1 есть и левая, и правая ветка.
* Но если посмотреть на левое поддерево узла 2, оно уходит слишком глубоко
  вниз (высота 3), в то время как правого ребенка у этой 2 вообще нет (высота
  0).
* Разница высот для узла 2 составляет 3 - 0 = 3. Это больше 1, поэтому дерево
  несбалансировано.

## Оптимальное решение: Считаем высоту и проверяем на лету

Можно было бы для каждого узла отдельно вызывать функцию maxDepth из прошлой
задачи. Но это заставило бы программу проходить по одним и тем же узлам много
раз, что дало бы плохую скорость O(N^2).
Хитрый приём: Мы можем модифицировать алгоритм подсчета высоты. Наша рекурсивная
функция будет возвращать высоту дерева, но если в какой-то момент она обнаружит
дисбаланс, она мгновенно вернет специальный флаг — -1.
Если снизу прилетело -1, то это значение просто пробрасывается на самый верх,
сигнализируя о том, что дерево сломано.

## Код на Kotlin

Вот чистое решение за один проход ($O(N)$ по времени):

```kotlin
// import kotlin.math.absimport kotlin.math.max
class Solution {
    fun isBalanced(root: TreeNode?): Boolean {
// Если функция возвращает -1, значит дерево несбалансировано
        return checkHeight(root) != -1
    }

    private fun checkHeight(root: TreeNode?): Int {
        // Базовый случай: высота пустого узла равна 0
        if (root == null) return 0

        // 1. Считаем высоту левого поддерева
        val leftHeight = checkHeight(root.left)
        // Если левая ветка уже несбалансирована, сразу возвращаем -1
        if (leftHeight == -1) return -1

        // 2. Считаем высоту правого поддерева
        val rightHeight = checkHeight(root.right)
        // Если правая ветка несбалансирована, сразу возвращаем -1
        if (rightHeight == -1) return -1

        // 3. Проверяем баланс ТЕКУЩЕГО узла
        // abs() находит модуль разницы (чтобы не важно было, какая ветка длиннее)
        if (abs(leftHeight - rightHeight) > 1) {
            return -1 // Дисбаланс найден!
        }

        // 4. Если всё в порядке, возвращаем реальную высоту текущего узла
        return max(leftHeight, rightHeight) + 1
    }
}


```

## Как это работает на примере поломки?

Вспомним левую ветку из Несбалансированного примера: 2 -> 3 -> 4.

1. Узел 4 (лист) возвращает высоту 1.
2. Узел 3 видит: левый ребенок (4) вернул 1, правого нет (0).
   Разница: 1 - 0 = 1. Всё ок. Узел 3 возвращает наверх свою высоту: max(1,0)
    + 1 = 2.
3. Узел 2 видит: левый ребенок (3) вернул высоту 2. А его левый ребенок 4 ушел
   еще ниже, поэтому реальная высота левой ветки для 2 равна 3. При этом правый
   ребенок у 2 отсутствует (0).
4. Узел 2 делает проверку: abs(3 - 0) > 1 -> ИСТИНА.
5. Узел 2 вместо высоты возвращает -1.
6. Корень 1 получает от левого ребенка -1, завершает все расчеты и выдает
   финальный false.
