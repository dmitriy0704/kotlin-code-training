# Структура TreeNode

Структура TreeNode — это базовый кирпичик для построения бинарных деревьев (
Binary Trees). Она устроена очень похоже на ListNode, который мы разбирали
ранее, но имеет одно ключевое отличие: у неё не одна следующая стрелка, а две.
На LeetCode структура TreeNode для Kotlin всегда объявлена следующим
образом:

```kotlin
class TreeNode(var `val`: Int) {
    var left: TreeNode? = null
    var right: TreeNode? = null
}

```

------------------------------

## Анатомия узла TreeNode

Каждый объект этого класса содержит три вещи:

1. val — данные, которые хранятся в узле (например, число).
2. left — ссылка на левого «ребенка» (такой же объект TreeNode) или null, если
   слева ничего нет.
3. right — ссылка на правого «ребенка» или null, если справа ничего нет.

Из-за того, что у каждого узла есть разветвление на два направления (left и
right), структура данных растет не в одну линию (как связный список), а ветвится
вниз, напоминая перевернутое дерево или генеалогическое древо.

## Визуальное представление в памяти

Представь, что мы создали дерево из трех элементов: на вершине стоит 1, слева от
нее 2, справа 3.
В памяти компьютера это три абсолютно независимых объекта, которые лежат в
разных ячейках памяти и просто ссылаются друг на друга адресами:

```text

               [ TreeNode 1 ]  (Корень / Root)
               val: 1
               left: 0xBBBB  ------------.
               right: 0xCCCC ------------|----.

                                         |    |
        .--------------------------------'    |
        v                                     v

[ TreeNode 2 ]                        [ TreeNode 3 ]

Адрес: 0xBBBB Адрес: 0xCCCC
val: 2 val: 3
left: null left: null
right: null right: null

```

## Как собрать дерево на Kotlin вручную?

Чтобы лучше понять эту структуру, давай соберем дерево из примера выше
программно, как это делает LeetCode под капотом:

```kotlin

fun main() {
// 1. Создаем три изолированных узла
    val root = TreeNode(1)
    val leftChild = TreeNode(2)
    val rightChild = TreeNode(3)

    // 2. Связываем их в единую структуру
    root.left = leftChild    // Теперь левая стрелка корня указывает на узел '2'
    root.right =
        rightChild  // Теперь правая стрелка корня указывает на узел '3'

    // 3. Можем уйти глубже и добавить ребенка для узла '2'
    leftChild.left = TreeNode(4)

}

```

## Ключевые термины, которые нужно знать:

* Корень (Root) — самый верхний узел дерева, у которого нет родителей (в коде
  выше это root). С него всегда начинается обход дерева.
* Лист (Leaf) — узел, у которого нет детей (и left, и right равны null). В
  нашем примере это узлы 3 и 4.
* Поддерево (Subtree) — любой узел вместе со всеми его потомками ниже по
  структуре. Например, leftChild вместе со своим ребенком 4 образуют целое
  «левое поддерево» для корня.

Именно благодаря тому, что любое поддерево само по себе является полноценным
деревом, задачи на TreeNode практически всегда решаются через рекурсию — мы
пишем логику для одного узла, а затем заставляем функцию повторить то же самое
для node.left и node.right.



# Как входные данные (массив) "превращаются" в дерево в задаче?

Нет, элементы массива в условии LeetCode — это не сами узлы дерева, а просто
текстовое представление структуры дерева, чтобы тебе было удобно читать
тесты [LicensedMediaService: fetch_images].
В коде на Kotlin никаких массивов в функцию не приходит. Функция принимает
полноценные объекты TreeNode? (корни деревьев).

## Как LeetCode превращает массив в дерево?

LeetCode использует стандартный способ записи бинарного дерева в строку, который
называется обходом по уровням (Level-order / BFS).
Массив расшифровывается строго по слоям сверху вниз, слева направо:

1. Первый элемент (1) — это всегда корень дерева (root).
2. Второй элемент (2) — это левый ребенок корня (root.left).
3. Третий элемент (3) — это правый ребенок корня (root.right).

Под капотом сайта скрытый код берет этот массив и превращает его в объекты в
памяти:

```kotlin
val p = TreeNode(1)
p.left = TreeNode(2)
p.right = TreeNode(3)

```

И именно этот объект p передается в твою функцию isSameTree(p, q).

## А если в дереве есть пустые места (null)?

Если бы у узла 2 не было детей, а у узла 3 был левый ребенок 4, дерево выглядело
бы так:

```text
      1
    /  \
   2    3
       /
      4
```


В интерфейсе LeetCode такой тест записали бы как массив:
p = [1, 2, 3, null, null, 4].
Сайт читает его так:

* Уровень 1: корень 1
* Уровень 2: дети корня — 2 и 3
* Уровень 3: дети узла 2 (оба null, то есть пустота) и дети узла 3 (левый 4,
  правого нет — он опущен, так как массив закончился).

Твой код работает напрямую с получившимися «живыми» объектами и их ссылками left
и right, а про существование исходного массива он даже не знает.
