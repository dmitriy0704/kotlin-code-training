# 104. Maximum Depth of Binary Tree

## Условие

Имея корень бинарного дерева, верните его максимальную глубину.

Максимальная глубина бинарного дерева — это количество узлов вдоль самого
длинного пути от корневого узла до самого дальнего листового узла.

Example 1:

![ex_104_1.jpg](../../../../../../imgs/ex_104_1.jpg)

Input: root = [3,9,20,null,null,15,7]
Output: 3

## Решение

Задача 104. Maximum Depth of Binary Tree (Максимальная глубина бинарного
дерева) — это идеальный пример для понимания того, как рекурсия умеет собирать и
суммировать информацию «снизу вверх», от листьев к корню.

## Суть задачи

Тебе дан корень бинарного дерева. Нужно найти его максимальную глубину (
высоту) — то есть количество узлов вдоль самого длинного пути от корневого узла
до самого дальнего листа.

## Суть рекурсивного решения

Представь, что ты стоишь в корне дерева и хочешь узнать его высоту. Как это
сделать?

1. Ты спрашиваешь своего левого ребенка: «Какова максимальная высота твоего
   поддерева?»
2. Ты спрашиваешь своего правого ребенка: «Какова максимальная высота твоего
   поддерева?»
3. Они уходят считать свою глубину по такому же принципу.
4. Когда они возвращаются с ответами (например, левый говорит «высота 3», а
   правый — «высота 1»), ты выбираешь максимальный из этих двух вариантов и
   прибавляешь 1 (самого себя).

Базовый случай (условие выхода): Если ты дошел до пустоты (null), то глубина
равна 0.

## Код на Kotlin

Благодаря встроенной функции maxOf, решение на Kotlin пишется буквально в одну
строку:

```kotlin
class Solution {
    fun maxDepth(root: TreeNode?): Int {
// Базовый случай: если узла нет, его глубина равна 0
        if (root == null) return 0

        // Считаем глубину левой и правой ветки, берем максимум и добавляем 1 (текущий узел)
        return maxOf(maxDepth(root.left), maxDepth(root.right)) + 1
    }

}
```

## Пошаговый разбор на примере

Возьмем дерево из примера LeetCode: root = [3, 9, 20, null, null, 15, 7]

```text
      3  <-- корень
     / \
    9  20
       / \
      15  7

```

Давай проследим, как раскрывается и закрывается рекурсия:

1. Вызывается maxDepth(3). Узел 3 не null, он ждет результатов от своих детей.
2. Идем влево: maxDepth(9).

    * Узел 9 проверяет своих детей — они оба null (возвращают 0).
    * Узел 9 считает: maxOf(0, 0) + 1 = 1. И возвращает 1 наверх узлу 3.

3. Идем вправо от корня: maxDepth(20). Он ждет результатов от своих детей (15 и
   7).

    * Узел 15 не имеет детей $\rightarrow$ возвращает 1.
    * Узел 7 не имеет детей $\rightarrow$ возвращает 1.
    * Узел 20 считает: maxOf(1, 1) + 1 = 2. И возвращает 2 наверх узлу 3.

4. Корень 3 наконец получил оба ответа: от левого (1) и от правого (2).
5. Итоговый расчет корня: maxOf(1, 2) + 1 = 2 + 1 = 3.

Функция возвращает 3. Самый длинный путь: 3 -> 20 -> 15 (или 3 -> 20 -> 7).

## 📊 Сложность

* Времени: O(N) — алгоритм обязан посетить каждый узел дерева ровно один раз,
  чтобы узнать его высоту.
* Памяти: O(H) — память в стеке вызовов. Для сбалансированного дерева
  это O(log N), для худшего случая (когда дерево вытянуто в одну
  линию) — O(N).

Эта задача часто открывает дверь к теме балансировки деревьев (например,
задача 110. Balanced Binary Tree), где нужно проверить, что высоты левого и
правого
поддеревьев отличаются не более чем на 1.
