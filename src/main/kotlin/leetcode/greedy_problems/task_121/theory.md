# Жадный алгоритм

Жадный алгоритм (Greedy Algorithm) — это метод решения задач, который на каждом
шагу делает локально оптимальный выбор в надежде, что в итоге получится
глобально оптимальное решение.
Простыми словами: алгоритм выбирает лучший (самый «выгодный») вариант прямо
сейчас, не заглядывая в будущее и не перебирая другие ветки развития
событий.

В Kotlin этот подход не зависит от самого языка, но лаконичные инструменты
Kotlin (такие как sortedByDescending, sumOf, функции коллекций) позволяют писать
такие алгоритмы очень чисто и компактно.

## Главный принцип жадного алгоритма

1. Жадно схватить лучшее: на каждом этапе берется самый крупный, самый дешевый
   или самый короткий элемент (в зависимости от задачи).
2. Никогда не возвращаться назад: в отличие от DFS (бэктрекинга), жадный
   алгоритм никогда не отменяет свои прошлые шаги. Сделал выбор — пошел дальше.

## Классический пример: Размен монет

Вам нужно выдать покупателю сдачу в 18 рублей минимальным количеством монет.
Доступны монеты номиналом: 10, 5, 2 и 1 рубль.
«Жадная» логика: каждый раз брать самую большую монету, которая помещается в
оставшуюся сумму.

## Реализация на Kotlin:

```kotlin

fun minCoins(coins: IntArray, target: Int): List<Int> {
    // 1. Сортируем монеты по убыванию (чтобы "жадно" брать самые крупные)
    val sortedCoins = coins.sortedDescending()
    val result = mutableListOf<Int>()
    var remaining = target

    // 2. Идем по монетам и берем их по максимуму
    for (coin in sortedCoins) {
        while (remaining >= coin) {
            remaining -= coin
            result.add(coin) // Забираем монету
        }
    }
    return result

}
fun main() {
    val availableCoins = intArrayOf(1, 2, 5, 10)
    val change = minCoins(availableCoins, 18)
    println(change) // Выведет: [10, 5, 2, 1] (всего 4 монеты)
}

```

## В чем подвох жадных алгоритмов?

Жадный алгоритм работает очень быстро (обычно за время сортировки O(N log N)
или просто за линейное время O(N)), но он не всегда дает правильный ответ.
Представьте, что из прошлого примера убрали монету 5, но добавили монету 7.
Номиналы: 10, 7, 1. Нам нужно набрать 14 рублей.

* Жадный алгоритм возьмет 10, останется 4. Затем возьмет четыре монеты по 1.
  Итог: [10, 1, 1, 1, 1] (5 монет).
* Идеальное решение: взять две монеты по 7. Итог: [7, 7] (2 монеты).

Жадный алгоритм с треском провалился, потому что выбрал 10 на первом шаге и
ослеп к более выгодной комбинации семерок. Задачи, где жадный алгоритм не
работает, обычно решаются через Динамическое программирование (DP).

## Шпаргалка для LeetCode: Когда применять?

Выбирайте жадный подход, если:

1. В задаче просят что-то минимизировать или максимизировать (например,
   минимальное число платформ для поездов, максимальная прибыль от акций).
2. Очевиден критерий выбора (сортировка по времени окончания, по стоимости за
   грамм, по размеру).

# Еще про жадный алгоритм

Конечно! Давай разберём **жадные алгоритмы** (greedy algorithms) — это ещё один
важный класс алгоритмов. В отличие от бинарного поиска, который строго
детерминирован, жадный подход больше про эвристику: мы принимаем локально
оптимальное решение на каждом шаге в надежде, что в итоге получим глобально
оптимальное.

## Основная идея жадного алгоритма

1. Есть задача, которую можно разбить на последовательность шагов/выборов.
2. На каждом шаге мы выбираем **наилучший локальный вариант** (жадный выбор), не
   думая о будущем.
3. После выбора мы его не пересматриваем (нет возврата назад).
4. Если повезёт, то к концу получим оптимальное решение.

## Когда жадный алгоритм работает?

Должны выполняться два свойства:

- **Свойство жадного выбора** (greedy choice property): глобальный оптимум можно
  получить последовательностью локально оптимальных выборов.
- **Свойство оптимальной подструктуры** (optimal substructure): оптимальное
  решение всей задачи содержит оптимальные решения подзадач.

Если эти свойства выполняются — жадный алгоритм даст правильный ответ. Если
нет — он может дать приближённое решение (иногда этого достаточно).

## Популярные примеры

- **Выдача сдачи монетами** (в некоторых номиналах)
- **Выбор активностей** (занятие аудиторий)
- **Задача о рюкзаке** (дробный вариант — жадный работает, целочисленный — нет)
- **Построение минимального остовного дерева** (алгоритмы Прима, Крускала)
- **Кодирование Хаффмана**

## Пример 1: Выдача сдачи (coin change) на Kotlin

Задача: есть монеты номиналом 1, 5, 10, 25. Нужно выдать сумму `n` минимальным
количеством монет.

**Жадная стратегия:** всегда брать монету максимального номинала, который не
превышает оставшуюся сумму.

```kotlin
fun greedyCoinChange(
    amount: Int,
    coins: IntArray = intArrayOf(25, 10, 5, 1)
): Map<Int, Int> {
    var remaining = amount
    val result = mutableMapOf<Int, Int>() // номинал -> количество

    for (coin in coins.sortedDescending()) { // идём от крупных к мелким
        if (remaining >= coin) {
            val count = remaining / coin
            result[coin] = count
            remaining -= count * coin
        }
    }

    return result
}

fun main() {
    val amount = 48
    val change = greedyCoinChange(amount)
    println("Сумма $amount: $change") // Сумма 48: {25=1, 10=2, 5=0, 1=3}
    // Итого монет: 1 + 2 + 0 + 3 = 6
}
```

**Почему работает?** Для стандартных номиналов (1,5,10,25) жадный даёт оптимум.
Для номиналов {1,3,4} и суммы 6 жадный возьмёт 4+1+1 (3 монеты), а оптимально
3+3 (2 монеты). Пример специально подобран, чтобы показать, что жадный не всегда
оптимален.

## Пример 2: Выбор активностей (Interval scheduling)

Задача: есть список задач с временем начала и конца. Нужно выбрать максимальное
количество непересекающихся задач.

**Жадная стратегия:** всегда выбирать задачу, которая заканчивается раньше всех,
и удалить все пересекающиеся с ней.

```kotlin
data class Activity(val start: Int, val end: Int)

fun selectMaxActivities(activities: List<Activity>): List<Activity> {
    if (activities.isEmpty()) return emptyList()

    // Сортируем по времени окончания
    val sorted = activities.sortedBy { it.end }

    val selected = mutableListOf<Activity>()
    var lastEnd = Int.MIN_VALUE

    for (act in sorted) {
        if (act.start >= lastEnd) {
            selected.add(act)
            lastEnd = act.end
        }
    }

    return selected
}

fun main() {
    val acts = listOf(
        Activity(1, 3),
        Activity(2, 5),
        Activity(3, 6),
        Activity(5, 7),
        Activity(6, 8)
    )
    val result = selectMaxActivities(acts)
    println("Выбрано ${result.size} активностей: $result")
    // Выбрано 3 активностей: [Activity(start=1, end=3), Activity(start=5, end=7), Activity(start=6, end=8)]
}
```

**Почему это правильно?** Доказано, что для задачи выбора активностей жадный
алгоритм, основанный на самом раннем завершении, даёт глобальный оптимум.

## Пример 3: Дробный рюкзак (fractional knapsack)

Задача: есть предметы с весом и ценой. Можно брать дробную часть предмета. Нужно
максимизировать ценность при ограничении по весу.

**Жадная стратегия:** сортируем по убыванию «плотности ценности» (цена/вес) и
набираем рюкзак.

```kotlin
data class Item(val weight: Double, val value: Double) {
    val density get() = value / weight
}

fun fractionalKnapsack(capacity: Double, items: List<Item>): Double {
    // Сортируем по плотности ценности убыванию
    val sorted = items.sortedByDescending { it.density }

    var remainingCap = capacity
    var totalValue = 0.0

    for (item in sorted) {
        if (remainingCap <= 0.0) break
        val takeWeight = minOf(item.weight, remainingCap)
        totalValue += takeWeight * item.density
        remainingCap -= takeWeight
    }

    return totalValue
}

fun main() {
    val items = listOf(
        Item(10.0, 60.0),   // плотность 6
        Item(20.0, 100.0),  // плотность 5
        Item(30.0, 120.0)   // плотность 4
    )
    val maxVal = fractionalKnapsack(50.0, items)
    println("Максимальная ценность: $maxVal") // берём первый целиком (10 веса, 60 цены), второй целиком (20 веса, 100 цены), третий 20 веса из 30 -> цена 80. Итого 240.0
}
```

Здесь жадный алгоритм даёт точное решение, потому что задача дробная.

## Сравнение: жадный vs динамическое программирование

| Жадный                                        | Динамическое программирование     |
|-----------------------------------------------|-----------------------------------|
| Локальный выбор                               | Рассматривает все варианты        |
| Не откатывается назад                         | Использует таблицу решений        |
| O(n log n) или O(n)                           | Часто O(n²) или больше            |
| Работает только для задач со спец. свойствами | Работает для более широкого круга |
| Проще в реализации                            | Сложнее                           |

## Когда жадный алгоритм не подходит?

- Классический **целочисленный рюкзак** (0/1). Жадный не даст оптимума.
- **Задача коммивояжёра** (жадный даст приближение, но не оптимум).
- **Размен монет** с произвольными номиналами (как упоминалось выше).

## Итог

Жадный алгоритм — это интуитивно понятный подход «бери лучшее сейчас». Он очень
эффективен и прост в реализации, но требует проверки: гарантирует ли он
оптимальное решение для твоей конкретной задачи. Если да — отлично! Если нет,
возможно, придётся использовать динамическое программирование или другие методы.
