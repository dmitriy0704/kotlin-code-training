# 455. Assign Cookies

Предположим, вы замечательный родитель и хотите угостить своих детей печеньем.
Но каждому ребенку следует дать не более одного печенья.

Каждый дочерний элемент i имеет коэффициент жадности g[i], представляющий
собой минимальный размер печенья, которым дочерний элемент будет доволен; и
каждый печенье j имеет размер s[j]. Если s[j] >= g[i], мы можем назначить
печенье j дочернему элементу i, и дочерний элемент i будет доволен. Ваша цель —
максимизировать количество дочерних элементов, довольных результатом, и вывести
максимальное их количество.

Example 1:

Input: g = [1,2,3], s = [1,1]
Output: 1
Пояснение: У вас 3 ребенка и 2 печенья. Факторы жадности 3 детей равны 1, 2, 3.
И даже если у вас есть 2 печеньки, поскольку их размер равен 1, вы можете
сделать контентом только того ребенка, у которого коэффициент жадности равен 1.
Вам нужно вывести 1.

Example 2:

Input: g = [1,2], s = [1,2,3]
Output: 2
Пояснение: У вас 2 ребенка и 3 печенья. Факторы жадности у 2 детей равны 1 и 2.
У вас есть 3 печеньки, и их размеры достаточно велики, чтобы удовлетворить
потребности всех дочерних элементов.
Вам нужно вывести 2.

## Решение

Рассмотрим одну из самых понятных и классических жадных задач на LeetCode — 455.
Assign Cookies (Раздача печенья). Она идеально объясняет, как работает
«близорукая» логика на практике.

## Условие задачи

Вы — хороший воспитатель и хотите порадовать детей печеньем.

* У вас есть массив детей g (greed), где g[i] — это аппетит $i$-го ребенка (
  минимальный размер печенья, который сделает его счастливым).
* У вас есть массив печенья s (size), где s[j] — это размер $j$-го печенья.

Если размер печенья s[j] >= g[i], вы можете отдать это печенье ребенку, и он
будет сыт. Один ребенок может получить только одно печенье. Ваша цель — сделать
сытыми максимальное количество детей.

## «Жадная» логика решения

Как поступить максимально эффективно?

1. Отсортируем детей по аппетиту (от самых скромных к самым прожорливым).
2. Отсортируем печенье по размеру (от самого маленького к самому большому).
3. Жадный выбор: Мы берем самого скромного ребенка и пытаемся дать ему самое
   маленькое печенье, которое ему подходит.

* Почему это жадно и правильно? Нет смысла тратить огромное печенье на ребенка с
  маленьким аппетитом, ведь это гигантское печенье может спасти прожорливого
  ребенка в будущем. Мы «жадничаем» ресурсы и отдаем самый маленький из
  возможных вариантов прямо сейчас.

## Реализация на Kotlin

```kotlin
class Solution {
    fun findContentChildren(g: IntArray, s: IntArray): Int {
// 1. Сортируем оба массива. Без этого "жадность" не сработает.
        g.sort() // Дети: от маленького аппетита к большому
        s.sort() // Печенье: от маленького размера к большому

        var childIndex = 0  // Указатель на текущего ребенка
        var cookieIndex = 0 // Указатель на текущее печенье

        // 2. Проходим по печенью и детям, пока они не закончатся
        while (childIndex < g.size && cookieIndex < s.size) {

            // Если текущее печенье подходит текущему ребенку
            if (s[cookieIndex] >= g[childIndex]) {
                // Ребенок сыт! Переходим к СЛЕДУЮЩЕМУ ребенку
                childIndex++
            }

            // В любом случае (подошло печенье или оказалось слишком мало) 
            // мы переходим к СЛЕДУЮЩЕМУ печенью. 
            // Маленькое неподошедшее печенье мы просто выбрасываем — 
            // другим более прожорливым детям оно тем более не подойдет.
            cookieIndex++
        }

        // Количество сытых детей будет равно индексу, 
        // до которого мы успели дойти в массиве детей g.
        return childIndex
    }

}


```

## Пример работы кода на пальцах

Дано:

* Аппетит детей: g = [1, 3, 2]
* Размеры печенья: s = [1, 1]

Шаг 1: Сортировка

* g = [1, 2, 3] (сначала накормим того, кому нужно 1, потом 2, потом 3)
* s = [1, 1]

Шаг 2: Цикл

1. Сравниваем g[0] (нужно 1) и s[0] (есть 1). Подходит! Первый ребенок сыт.
   Сдвигаем оба указателя: childIndex = 1, cookieIndex = 1.
2. Сравниваем g[1] (нужно 2) и s[1] (есть 1). Не подходит! Печенье слишком
   маленькое. Ребенок остается голодным. Сдвигаем только указатель печенья:
   cookieIndex = 2.
3. Печенье закончилось (cookieIndex == s.size). Цикл завершен.

Функция возвращает childIndex = 1 (накормили ровно одного ребенка).

## Почему этот алгоритм жадный?

Потому что мы ни на секунду не задумывались о глобальной стратегии. Мы просто
шли с начала списков и принимали лучшее локальное решение на каждом шагу: «Дает
ли это конкретное маленькое печенье сытость этому конкретному скромному ребенку?

Да — отдаем. Нет — берем другое печенье».
