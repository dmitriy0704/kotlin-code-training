# Теория по LinkedList

Для успешного решения задач на тему **связных списков (Linked List)** на
LeetCode с использованием **Kotlin**, нужно освоить не только базовые концепции,
но и ключевые паттерны решения, а также учесть особенности этого языка.

Вот структурированный план того, что вам нужно знать.

### 1. Базовые концепции и операции

Прежде всего, необходимо твёрдо понимать, что такое связный список и чем он
отличается от массива. В отличие от массива, элементы списка не хранятся в
памяти последовательно, а связаны между собой с помощью ссылок (указателей).

* **Типы списков**: Односвязный (Singly), двусвязный (Doubly) и кольцевой (
  Circular).
* **Структура узла (`ListNode`)**: В задачах LeetCode на Kotlin узел обычно
  выглядит так:
  ```kotlin
  class ListNode(var `val`: Int) {
      var next: ListNode? = null
  }
  ```
  Обратите внимание на использование обратных кавычек для поля `val`, так как
  `val` является зарезервированным словом в Kotlin.
* **Ключевые операции**:
    * **Вставка**: в начало, в конец, в середину списка.
    * **Удаление**: по значению или по позиции.
    * **Обход (Traversal)**: итеративный и рекурсивный.

### 2. Основные паттерны решения задач (Must-Know)

Это самое важное. Большинство задач на LeetCode строятся вокруг нескольких
повторяющихся паттернов. Освоив их, вы сможете решить подавляющее большинство
задач.

* **Техника двух указателей (Fast & Slow Pointers / Tortoise and Hare)**:
  Это, пожалуй, самый универсальный паттерн. Один указатель (`slow`) двигается
  на один шаг, а второй (`fast`) — на два.
    * **Где применяется**: Поиск середины списка, обнаружение цикла (алгоритм
      Флойда), поиск K-го элемента с конца.
    * **Преимущество**: Позволяет решать задачи за O(n) времени и O(1)
      дополнительной памяти.

* **Техника фиктивного узла (Dummy Node)**:
  Это ваш лучший друг для обработки краевых случаев. Вы создаете временный
  узел (`dummy`), который указывает на голову (`head`) списка.
    * **Где применяется**: Все задачи, где голова списка может измениться:
      удаление головы, реверс, слияние списков, разбиение (partition).
    * **Преимущество**: Упрощает код, так как вам не нужно писать отдельную
      логику для случая, когда операция затрагивает первый узел.

* **Реверс (Reversal) списка (или его части)**:
  Классическая операция, которая требует аккуратного обращения с тремя
  указателями.
    * **Где применяется**: Разворот всего списка, разворот части списка,
      разворот по K групп (`Reverse Nodes in k-Group`).

* **Рекурсия**:
  Многие задачи со списками (особенно те, что связаны с обходом или слиянием)
  имеют элегантное рекурсивное решение.

### 3. Что нужно знать в Kotlin

Помимо общих паттернов, обратите внимание на следующие аспекты Kotlin:

* **Null Safety**: Поле `next` в `ListNode` объявлено как `ListNode?`, что
  означает, что оно может быть `null`. Kotlin заставляет вас явно обрабатывать
  возможность `null`. Это делает код более безопасным, но требует привыкания при
  навигации по списку (например, используйте `?.` и `?:`).
* **Иммутабельность**: В задачах LeetCode часто просят вернуть новый список, не
  изменяя исходный. Помните, что `val` в Kotlin — это неизменяемая ссылка, но
  сам объект, на который она ссылается, может быть изменен (например, можно
  менять `next`).
* **Стандартная библиотека**: Хотя в чистых задачах на списки она используется
  редко, знание функций работы с коллекциями может пригодиться для
  вспомогательных операций.
