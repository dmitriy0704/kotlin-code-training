# In place algorithm

In-place алгоритм (или алгоритм «на месте») — это метод, который преобразует
структуру данных без использования дополнительной памяти пропорционально размеру
входных данных.
Главное требование таких задач на LeetCode — уложиться в память O(1).

## Суть in-place алгоритма

Вам запрещено создавать новый массив, новый список или новую строку для
сохранения результата. Вы должны изменять исходный объект, который вам передали
в функцию в качестве аргумента.

## Как делать НЕЛЬЗЯ (Не in-place, память O(N)):

Вы создаете копию или новую структуру.

```kotlin
// Создает новый массив в памяти, старый остается нетронутым

fun reverseString(s: CharArray) {
    val result = s.reversedArray()
// На LeetCode это выдаст ошибку, так как исходный массив `s` не изменился
}

```

## Как НУЖНО (In-place, память O(1)):

Вы модифицируете только переданный массив s, используя пару указателей.

```kotlin
fun reverseString(s: CharArray) {
    var left = 0
    var right = s.size - 1

    while (left < right) {
        // Меняем элементы местами прямо внутри массива s
        val temp = s[left]
        s[left] = s[right]
        s[right] = temp

        // Сдвигаем указатели навстречу друг другу
        left++
        right--
    }

}

```


## Почему это важно для LeetCode и продакшена?

1. Экономия памяти: Если на вход подадут массив из 10 gigabytes данных, in-place
   алгоритм использует те же 10 гигабайт. Обычный алгоритм потребует еще 10
   гигабайт сверху для создания копии.
2. Ограничения платформы: В задаче 344 система тестирования LeetCode проверяет
   именно исходный массив s после завершения вашей функции. Если вы запишете
   ответ в другую переменную, тесты просто увидят исходную строку без изменений.

У этой задачи есть красивый трюк в Kotlin: вместо ручного создания переменной
temp для обмена, можно использовать встроенную функцию или решить её в одну
строчку.
