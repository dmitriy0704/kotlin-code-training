# 344. Reverse String

## Условие

Напишите функцию, которая переворачивает строку. Входная строка задана в виде
массива символов.

Для этого необходимо модифицировать входной массив на месте, используя
дополнительную память O(1).

Example 1:
Input: s = ["h","e","l","l","o"]
Output: ["o","l","l","e","h"]

Example 2:
Input: s = ["H","a","n","n","a","h"]
Output: ["h","a","n","n","a","H"]

## Решение

In-place алгоритм (или алгоритм «на месте») — это метод, который преобразует
структуру данных без выделения дополнительной памяти, пропорциональной размеру
ввода. Ваша программа должна уложиться в константную память O(1). В задаче 344.
Reverse String вам на вход подается массив символов s: CharArray.
Смысл in-place требования здесь в том, что вам запрещено создавать новый массив,
разворачивать его туда, а потом копировать обратно. Изменения нужно вносить
прямо в переданный массив s.
Вот классическое решение этой задачи на Kotlin с использованием метода двух
указателей:

```kotlin
class Solution {
    fun reverseString(s: CharArray): Unit {
        // Указатель на начало массива
        var left = 0

        // Указатель на конец массива
        var right = s.size - 1

        // Двигаем указатели навстречу друг другу, пока они не встретятся в центре
        while (left < right) {
            // Временная переменная для обмена (занимает O(1) памяти)
            val temp = s[left]

            // Меняем символы местами прямо в исходном массиве
            s[left] = s[right]
            s[right] = temp

            // Сдвигаем указатели к центру
            left++
            right--
        }
    }

}
```

## Как это работает "in-place" на примере s = ["h","e","l","l","o"]

1. Старт: left = 0 (буква 'h'), right = 4 (буква 'o').

    * Меняем их местами.
    * Массив изменился прямо в памяти: ["o","e","l","l","h"].

2. Шаг 2: left = 1 (буква 'e'), right = 3 (буква 'l').

    * Меняем их местами.
    * Массив стал: ["o","l","l","e","h"].

3. Конец: left = 2, right = 2. Условие left < right больше не выполняется. Цикл
   завершен.

## Трюк в стиле Kotlin

Если на собеседовании вас попросят написать этот же in-place алгоритм, но
красивым лаконичным кодом на Kotlin, можно использовать встроенную функцию
reverse() для массивов. Она написана под капотом точно так же (in-place через
указатели), но выглядит аккуратно:

```kotlin
class Solution {
    fun reverseString(s: CharArray): Unit {
        s.reverse() // Изменяет массив "на месте", не создавая копий
    }
}
```

# Еще

Отлично, давайте решим **задачу 344. Reverse String** на Kotlin. Она очень
простая, но важно правильно реализовать её **in-place** (без выделения
дополнительной памяти под новую строку/массив).

---

## 📌 Условие

На вход подаётся массив символов `s`. Нужно **перевернуть** его на месте,
изменив порядок символов на противоположный.  
Нельзя возвращать новый массив – меняем исходный.

Пример:

- Вход: `['h','e','l','l','o']` → Выход: `['o','l','l','e','h']`

---

## 💡 Идея решения (Two Pointers)

Используем два указателя:

- `left` – указывает на первый символ (индекс 0).
- `right` – указывает на последний символ (индекс `s.size - 1`).

Меняем местами символы, на которые указывают `left` и `right`, затем сдвигаем
`left` вправо, `right` влево. Продолжаем, пока `left < right`.

---

## 🧠 Сложность

- **Время:** O(n) – один проход по половине массива.
- **Память:** O(1) – используем только две переменные для индексов и одну для
  временного хранения.

---

## 💻 Код на Kotlin

```kotlin
class Solution {
    fun reverseString(s: CharArray): Unit {
        var left = 0
        var right = s.size - 1

        while (left < right) {
            // Меняем местами s[left] и s[right]
            val temp = s[left]
            s[left] = s[right]
            s[right] = temp

            left++
            right--
        }
    }
}
```

---

## 🔍 Альтернативы (и почему их лучше избегать на собеседовании)

- **Встроенная функция `s.reverse()`** – делает то же самое, но на собеседовании
  ожидают ручную реализацию, чтобы показать понимание алгоритма.
- **Создание новой строки/массива** – например, `s = s.reversedArray()` – это не
  in-place и потребляет O(n) памяти, что нарушает условие задачи.

---

## 📝 Проверка на примере

```kotlin
fun main() {
    val s = charArrayOf('h', 'e', 'l', 'l', 'o')
    Solution().reverseString(s)
    println(s.joinToString()) // o, l, l, e, h
}
```

---

## 🧩 Почему это работает?

Цикл обменивает символы с двух концов, постепенно сближаясь к центру. Как только
указатели встречаются или пересекаются – все элементы уже попарно обменяны.

---

## 💡 Возможные вопросы на собеседовании

- **Что будет с пустым массивом?** → цикл не запустится, всё корректно.
- **Что будет с массивом из одного элемента?** → left = right = 0, цикл не
  выполняется, порядок не меняется – тоже верно.
- **Можно ли использовать `s.reverse()`?** – да, но мы показываем, что знаем,
  как это работает под капотом.

---

Отличный вопрос! Это фундаментальный момент, который часто сбивает с толку
новичков. Давайте разберёмся на пальцах, почему `temp` (временная переменная) *
*обязательна**, и что случится, если её не использовать.

---

## 🧪 Что произойдёт, если просто написать `s[left] = s[right]`?

Представьте массив: `['h', 'e', 'l', 'l', 'o']`  
Нам нужно поменять местами `s[0] = 'h'` и `s[4] = 'o'`.

Если мы попробуем сделать это **без** `temp`:

```kotlin
s[left] = s[right]  // теперь s[0] = 'o' (мы потеряли 'h'!)
s[right] = s[left]  // а здесь s[4] = s[0] = 'o', получаем 'o' и там, и там
```

В результате массив станет `['o', 'e', 'l', 'l', 'o']` – мы потеряли букву `'h'`
безвозвратно! 😱

---

## 💡 Зачем нужен `temp`?

`temp` – это **карман**, куда мы кладём одно из значений, чтобы оно не пропало,
пока мы перезаписываем ячейку.

Правильная последовательность:

```kotlin
val temp = s[left]   // сохраняем 'h' в карман
s[left] = s[right]   // теперь s[0] = 'o' (старое 'h' уже в кармане)
s[right] = temp      // берём 'h' из кармана и кладём в s[4]
```

Теперь массив правильно стал `['o', 'e', 'l', 'l', 'h']` – всё поменялось.

---

## 🔄 А если мы пробегаемся по строке и меняем местами «на ходу»?

Вы могли подумать: «А что, если я просто проиду по строке слева направо и буду
каждому элементу присваивать значение с противоположного конца?» – это не
сработает, потому что:

- Когда вы дойдёте до середины, вы уже **перезапишете** все левые элементы, и
  правые значения, которые вы хотите использовать, будут утеряны.
- Вам нужна синхронная замена двух элементов одновременно, а не последовательное
  присваивание.

Именно поэтому алгоритм с двумя указателями и обменом через `temp` – это
классика.

---

## 🧠 Есть ли альтернативы `temp` в Kotlin?

Да, Kotlin позволяет сделать обмен более компактно (но под капотом всё равно
используется временная переменная):

**Способ 1 – через `also` (функциональный стиль):**

```kotlin
s[left] = s[right].also { s[right] = s[left] }
```

Этот трюк работает так: `s[right].also { ... }` сначала читает значение
`s[right]`, затем выполняет блок `{ s[right] = s[left] }`, а затем возвращает
прочитанное значение, которое присваивается `s[left]`. Эффект тот же, но без
явного `temp`. Однако на собеседовании такой код могут счесть менее читаемым,
особенно если интервьюер не знаком с `also`.

**Способ 2 – использовать встроенную функцию `reverse()`** – но она скрывает
детали, и для учебных целей мы её не используем.

---

## 🎯 Итог

- `temp` нужна, чтобы **сохранить** значение одной переменной, пока мы
  перезаписываем другую.
- Без неё мы потеряем данные и получим неверный результат.
- Это базовый паттерн обмена значениями, который встречается не только в
  строках, но и в сортировках, перестановках и т.д.
