# 5. Longest Palindromic Substring

## Условие

Дана строка s. Верните самую длинную палиндромную подстроку в строке s.

Example 1:
Input: s = "babad"
Output: "bab"
Explanation: "aba" is also a valid answer.

Example 2:
Input: s = "cbbd"
Output: "bb"

Constraints:
1 <= s.length <= 1000
s consist of only digits and English letters.

## Решение

Отлично, давайте разберём **задачу 5. Longest Palindromic Substring** на
Kotlin.  
Я покажу классическое и эффективное решение через **расширение от центра** – оно
простое для понимания, даёт O(n²) и проходит все тесты на LeetCode.

---

## 📌 Условие

Дана строка `s`. Нужно найти **самую длинную подстроку**, которая читается
одинаково слева направо и справа налево (палиндром). Если таких несколько –
вернуть любую.

Примеры:

- `"babad"` → `"bab"` (или `"aba"`)
- `"cbbd"` → `"bb"`
- `"a"` → `"a"`

---

## 💡 Идея решения: расширение от центра

Палиндром можно «вырастить» из центра, расширяя границы влево и вправо, пока
символы совпадают.  
Центром может быть:

- **один символ** – для нечётной длины (например, `"aba"` имеет центр `'b'`);
- **два соседних символа** – для чётной длины (например, `"abba"` имеет центр
  между `'b'` и `'b'`).

Мы перебираем все возможные центры (их `2*n - 1`) и для каждого находим
максимальную длину палиндрома, обновляя глобальный ответ.

---

## 🧠 Алгоритм по шагам

1. Инициализируем переменные `start = 0`, `maxLen = 1` (минимальный ответ –
   первый символ).
2. Проходим по индексу `i` от `0` до `n-1`:
    - **Нечётный центр** – расширяем от `(i, i)`.
    - **Чётный центр** – расширяем от `(i, i+1)`.
3. Для каждого центра вызываем функцию `expand(left, right)`, которая:
    - Пока `left >= 0`, `right < n` и `s[left] == s[right]` – двигаем `left--`,
      `right++`.
    - Возвращает длину палиндрома: `right - left - 1`.
4. Если полученная длина больше `maxLen`, обновляем `maxLen` и
   `start = left + 1`.
5. В конце возвращаем `s.substring(start, start + maxLen)`.

---

## 💻 Код на Kotlin

```kotlin
class Solution {
    fun longestPalindrome(s: String): String {
        if (s.length < 2) return s

        var start = 0
        var maxLen = 1

        fun expandAroundCenter(left: Int, right: Int): Int {
            var l = left
            var r = right
            while (l >= 0 && r < s.length && s[l] == s[r]) {
                l--
                r++
            }
            return r - l - 1  // длина палиндрома
        }

        for (i in s.indices) {
            // Нечётная длина
            val len1 = expandAroundCenter(i, i)
            // Чётная длина
            val len2 = expandAroundCenter(i, i + 1)

            val maxLenHere = maxOf(len1, len2)
            if (maxLenHere > maxLen) {
                maxLen = maxLenHere
                // Новый старт – левая граница палиндрома
                // При длине len центр был в (i, i) или (i, i+1)
                // Формула: left = i - (len - 1) / 2  (для нечётного)
                //         left = i - (len - 2) / 2  (для чётного) – но проще через смещение
                start = i - (maxLenHere - 1) / 2
            }
        }

        return s.substring(start, start + maxLen)
    }
}
```

---

## 🔍 Объяснение ключевых моментов

- **Функция `expandAroundCenter`** возвращает длину, а не саму строку – это
  упрощает код и переиспользование.
- **Формула для `start`**:  
  Для нечётного центра `(i, i)`: если длина = `len`, то левая граница =
  `i - len/2`.  
  Для чётного центра `(i, i+1)`: левая граница = `i - (len/2 - 1)`.  
  Универсальная формула `i - (len - 1) / 2` работает для обоих случаев (
  проверьте на примерах).
- Перебор центров: для каждого `i` мы проверяем два центра – это даёт все
  возможные палиндромы.

---

## ⏱ Сложность

- **Время:** O(n²) – для каждого из `2n-1` центров расширение в худшем случае
  идёт O(n).
- **Память:** O(1) – используем только несколько переменных.

---

## 🔁 Альтернативные подходы

- **Динамическое программирование** – O(n²) времени и O(n²) памяти (таблица
  `dp[i][j]`). Менее предпочтительно из-за памяти.
- **Алгоритм Манахера** – O(n) времени и O(n) памяти, но сложнее в реализации.
  На LeetCode его редко просят, но знать о нём полезно.

# Еще про центр

Отличный вопрос! Это **самый частый момент непонимания** в этой задаче.

Дело в том, что в реальной жизни мы интуитивно ищем центр в букве (как в слове *
*"топот"** — центр в букве **"п"**). Но программист должен помнить, что
палиндромы бывают **чётной длины**, где центра *между буквами* нет, а есть
только **воображаемая щель**.

Давайте разберем это на пальцах и картинках. 🖐️

---

### 1. Где вообще находятся центры?

Возьмем строку `s = "b a b a d"` (длина `n = 5`).
Если мы пронумеруем **позиции символов** (от 0 до 4) и **щели между ними** (
включая края), то центров у нас ровно `2n - 1 = 9` штук.

Визуализация (символы `|` — это щели):
`| b | a | b | a | d |`
Индексы символов: `0   1   2   3   4`

Наш алгоритм заходит в цикл по индексу `i` (от 0 до 4). На каждой итерации мы
проверяем **два типа центра**:

| Итерация `i` | **1-й центр (нечётный)**      | **2-й центр (чётный)**                                                                                       |
|:-------------|:------------------------------|:-------------------------------------------------------------------------------------------------------------|
| `i = 0`      | Центр **в** символе `b` (0,0) | Центр **между** `b` и `a` (щель перед `a`) (0,1)                                                             |
| `i = 1`      | Центр **в** символе `a` (1,1) | Центр **между** `a` и `b` (1,2)                                                                              |
| `i = 2`      | Центр **в** символе `b` (2,2) | Центр **между** `b` и `a` (2,3)                                                                              |
| `i = 3`      | Центр **в** символе `a` (3,3) | Центр **между** `a` и `d` (3,4)                                                                              |
| `i = 4`      | Центр **в** символе `d` (4,4) | Центр **между** `d` и концом строки (4,5) — <br> ↳ этот вызов ничего не даст, т.к. правая граница вне строки |

---

### 2. Почему мы проверяем именно `(i, i)` и `(i, i+1)`?

- **Случай 1:** `expand(i, i)` — мы ставим левый и правый палец в одну и ту же
  букву. Если строка **"b a b"** (индекс `i=1` — это буква `a`), то:
    - Сравниваем `s[1]` и `s[1]` (совпадают) → двигаем пальцы влево-вправо.
    - Сравниваем `s[0]` (`b`) и `s[2]` (`b`) → совпадают. → Получили `"bab"`.

- **Случай 2:** `expand(i, i+1)` — мы ставим левый палец на букву, а правый — *
  *сразу на следующую букву**. Это и есть центр в **щели**.
    - Возьмем строку **"c b b d"**. Нам нужно найти `"bb"`.
    - Когда цикл дойдет до `i = 1` (первая буква `b`), мы вызываем
      `expand(1, 2)`.
    - Левый палец смотрит на `s[1] = 'b'`, правый — на `s[2] = 'b'`.
    - Они равны! → расширяемся. Получили палиндром длины 2.

---

### 3. Почему мы не пишем `while (i < s.length)` для второго центра отдельно?

В коде мы просто пишем `expandAroundCenter(i, i + 1)`. Если `i` — последний
символ, то `i+1` будет равен длине строки (например, 5).
Внутри функции `expand` есть условие `while (l >= 0 && r < s.length && ...)`.
Так как `r < s.length` (5 < 5) — это `false`, цикл даже не запустится, и функция
сразу вернет длину 1 (или 0). Ошибки выхода за границу не будет.

---

### 4. Как формула `start = i - (maxLenHere - 1) / 2` находит центр?

Это чистая математика на целочисленном делении. Давайте проверим на двух
примерах, чтобы убедиться, что мы правильно нашли центр (левую границу):

- **Нечётный** (`"bab"`, центр в `i=1`, длина `len=3`):  
  `start = 1 - (3 - 1) / 2 = 1 - 2/2 = 1 - 1 = 0`. Всё верно, строка начинается
  с индекса 0.

- **Чётный** (`"bb"` в строке `"cbbd"`, левая буква `b` имеет индекс `i=1`,
  длина `len=2`):  
  `start = 1 - (2 - 1) / 2 = 1 - 1/2 = 1 - 0 = 1` (деление целочисленное).  
  Всё верно, подстрока `"bb"` начинается с индекса 1.

---

### 💡 Самая простая ментальная модель для запоминания

Просто запомните правило:
> **Мы перебираем все буквы строки по очереди.**
> Для каждой буквы `i` мы пытаемся вырастить палиндром:
> 1. Вокруг **самой этой буквы** (если палиндром нечётный).
> 2. Вокруг **щели между этой буквой и её правой соседкой** (если палиндром
     чётный).

То есть мы физически не ищем центры сложным способом. Мы просто говорим: *«А
давай-ка проверим все возможные места, где может быть центр. Их ровно по 2 на
каждую позицию символа»*.
