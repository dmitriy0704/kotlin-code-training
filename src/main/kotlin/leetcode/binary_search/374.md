# 374. Guess Number Higher or Lower

## Условие

Мы играем в игру «Угадай». Правила игры следующие:

Я выбираю число от 1 до n. Вы должны угадать, какое число я выбрал (выбранное
мной число остается неизменным на протяжении всей игры).

Каждый раз, когда вы ошибаетесь в своих предположениях, я буду сообщать вам,
больше или меньше выбранное мной число, чем ваше предположение.

Вы вызываете предопределенный API-функцию `int guess(int num)`, которая
возвращает три возможных результата:

- -1: Ваша догадка больше, чем число, которое я выбрал (т.е. число > выбранное).
- 1: Ваше предположение меньше выбранного мной числа (т.е. число < выбранное).
- 0: ваша догадка равна выбранному мной числу (т.е. num == pick).

Верните выбранное мной число.

Example 1:
Input: n = 10, pick = 6
Output: 6

Example 2:
Input: n = 1, pick = 1
Output: 1

Example 3:
Input: n = 2, pick = 1
Output: 1

Constraints:

1 <= n <= 231 - 1
1 <= pick <= n

## Решение

## Задача 374. Guess Number Higher or Lower

В этой задаче «загадано» некоторое число от 1 до `n`, но оно **не передаётся** в
вашу функцию в качестве аргумента. Вместо этого платформа LeetCode предоставляет
вам **встроенный API** — функцию `guess(num: Int): Int`, которая для каждого
переданного вами числа `num` возвращает:

- `-1`, если загаданное число **меньше** `num` (т.е. `num` слишком большое),
- `1`, если загаданное число **больше** `num` (т.е. `num` слишком маленькое),
- `0`, если вы угадали.

Эта функция скрыто обращается к числу, которое хранится в тестовой системе — вы
его не видите, но можете взаимодействовать с ним через вызовы `guess`. Ваша
задача — угадать это число, сделав как можно меньше вызовов.

---

## Почему здесь нужен бинарный поиск?

По сути, перед нами отсортированный диапазон чисел `[1, n]`, и для любого `num`
мы можем получить ответ: «загаданное число меньше/больше/равно». Это полностью
аналогично бинарному поиску в отсортированном массиве: вместо сравнения с
`target` мы сравниваем с результатом `guess(mid)`:

- Если `guess(mid) == 0` → нашли ответ.
- Если `guess(mid) == -1` → загаданное число меньше, значит, ищем в левой
  половине (`right = mid - 1`).
- Если `guess(mid) == 1` → загаданное число больше, значит, ищем в правой
  половине (`left = mid + 1`).

Таким образом, сложность O(log n), и мы используем ту же логику, что в
классическом бинарном поиске.

## Реализация на Kotlin

В LeetCode шаблон выглядит примерно так:

```kotlin
/** 
 * The API guess is defined in the parent class.
 * @param  num   your guess
 * @return       -1 if num is higher than the picked number
 *                1 if num is lower than the picked number
 *                otherwise return 0
 * fun guess(num: Int): Int {}
 */
class Solution : GuessGame() {
    fun guessNumber(n: Int): Int {
        var left = 1
        var right = n
        while (left <= right) {
            val mid = left + (right - left) / 2
            when (guess(mid)) {
                0 -> return mid
                -1 -> right = mid - 1
                1 -> left = mid + 1
            }
        }
        return -1 // никогда не должно выполняться, так как ответ всегда есть
    }
}
```

### Пояснение к коду

- Наследуемся от `GuessGame` — это класс, предоставленный LeetCode, в котором
  определена функция `guess`.
- Инициализируем границы `[1, n]`, так как загаданное число точно лежит в этом
  диапазоне.
- В цикле вычисляем `mid`, вызываем `guess(mid)` и сужаем интервал согласно
  результату.
- Если выходим из цикла (что теоретически невозможно, потому что ответ всегда
  существует), возвращаем `-1` (или можно выбросить исключение).

---

## Почему загаданное число не передаётся?

Потому что задача спроектирована так, чтобы вы **имитировали процесс угадывания
** — как в игре «больше-меньше». В реальных приложениях часто бывает, что у вас
есть внешний сервис, который отвечает на запросы, и вам нужно найти нужное
значение, делая минимальное количество запросов.

Вместо того чтобы дать вам готовый массив, система прячет число за интерфейсом
`guess`, чтобы вы тренировались работать с таким «чёрным ящиком». Это типичный
паттерн для задач на бинарный поиск по ответу.

---

## Пример работы

Пусть `n = 10`, загадано `6`.

1. `left = 1, right = 10, mid = 5` → `guess(5)` → загаданное больше → возвращает
   `1` → `left = 6`
2. `left = 6, right = 10, mid = 8` → `guess(8)` → загаданное меньше → возвращает
   `-1` → `right = 7`
3. `left = 6, right = 7, mid = 6` → `guess(6)` → `0` → возвращаем `6`.

Всё работает!

---

## Важные замечания

- Не забывайте использовать `left + (right - left) / 2`, чтобы избежать
  переполнения.
- Если в языке нет встроенной функции `guess`, её предоставляет платформа, вы
  просто её вызываете.
- В некоторых реализациях используется полуоткрытый интервал `[left, right)` —
  можно и так, но для этой задачи замкнутый интервал проще и интуитивнее.

## Сложность

- **Время**: O(log n), так как каждое угадывание уменьшает диапазон вдвое.
- **Память**: O(1) — используем только несколько переменных.
