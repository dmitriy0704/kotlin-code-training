# 35. Search Insert Position

## Условие

Имея отсортированный массив различных целых чисел и целевое значение, верните
индекс, если целевое значение найдено. В противном случае верните индекс, по
которому оно находилось бы, если бы было вставлено в порядке возрастания.

Вам необходимо написать алгоритм со сложностью выполнения O(log n).

Example 1:
Input: nums = [1,3,5,6], target = 5
Output: 2

Example 2:
Input: nums = [1,3,5,6], target = 2
Output: 1

Example 3:
Input: nums = [1,3,5,6], target = 7
Output: 4

Constraints:
1 <= nums.length <= 104
-104 <= nums[i] <= 104
nums contains distinct values sorted in ascending order.
-104 <= target <= 104

## Решение

## Задача 35. Search Insert Position

### Условие

Дан **отсортированный** по возрастанию массив целых чисел `nums` и число
`target`.  
Нужно вернуть **индекс**, где должен находиться `target`, если он есть в
массиве. Если его нет, вернуть индекс, куда его следует вставить, чтобы
сохранить сортировку.

**Примеры:**

- `nums = [1,3,5,6]`, `target = 5` → возвращаем `2` (индекс числа 5).
- `nums = [1,3,5,6]`, `target = 2` → возвращаем `1` (между 1 и 3).
- `nums = [1,3,5,6]`, `target = 7` → возвращаем `4` (в конец).
- `nums = [1,3,5,6]`, `target = 0` → возвращаем `0` (в начало).

---

### Идея решения

Это классический бинарный поиск с одной модификацией: если мы не находим
`target`, мы должны вернуть позицию, где он должен стоять.  
В стандартном бинарном поиске, когда мы выходим из цикла (при `left > right`),
переменная `left` указывает на позицию вставки, потому что мы постоянно сдвигаем
`left` вправо, когда `target` больше `nums[mid]`, и `right` влево, когда
`target` меньше. По окончании цикла `left` будет указывать на первый элемент,
который больше или равен `target` (то есть место вставки).

Можно использовать реализацию поиска **левой границы** (lower_bound) — она
идеально подходит, потому что мы ищем первое место, где `nums[index] >= target`.

---

### Реализация на Kotlin

```kotlin
class Solution {
    fun searchInsert(nums: IntArray, target: Int): Int {
        var left = 0
        var right = nums.lastIndex

        while (left <= right) {
            val mid = left + (right - left) / 2
            when {
                nums[mid] == target -> return mid
                nums[mid] < target -> left = mid + 1
                else -> right = mid - 1
            }
        }
        return left
    }
}
```

**Альтернативный вариант с полуоткрытым интервалом (часто используется для
lower_bound):**

```kotlin
class Solution {
    fun searchInsert(nums: IntArray, target: Int): Int {
        var left = 0
        var right = nums.size // right не включительно
        while (left < right) {
            val mid = left + (right - left) / 2
            if (nums[mid] >= target) {
                right = mid
            } else {
                left = mid + 1
            }
        }
        return left
    }
}
```

Оба варианта корректны, но первый проще для понимания, если ты уже освоил
классический бинарный поиск.

---

### Пошаговое объяснение (на примере)

**Пример 1:** `nums = [1,3,5,6]`, `target = 5`

- `left=0, right=3, mid=1` → `nums[1]=3 < 5` → `left=2`
- `left=2, right=3, mid=2` → `nums[2]=5 == 5` → возвращаем `2`.

**Пример 2:** `nums = [1,3,5,6]`, `target = 2`

- `left=0, right=3, mid=1` → `nums[1]=3 > 2` → `right=0`
- `left=0, right=0, mid=0` → `nums[0]=1 < 2` → `left=1`
- `left=1, right=0` → выход из цикла, возвращаем `left=1`. Вставляем между 1 и
    3.

**Пример 3:** `nums = [1,3,5,6]`, `target = 7`

- `left=0, right=3, mid=1` → `3 < 7` → `left=2`
- `left=2, right=3, mid=2` → `5 < 7` → `left=3`
- `left=3, right=3, mid=3` → `6 < 7` → `left=4`
- `left=4, right=3` → выход, возвращаем `4` (вставка в конец).

**Пример 4:** `nums = [1,3,5,6]`, `target = 0`

- `left=0, right=3, mid=1` → `3 > 0` → `right=0`
- `left=0, right=0, mid=0` → `1 > 0` → `right=-1`
- `left=0, right=-1` → выход, возвращаем `0` (вставка в начало).

---

### Почему возвращаем `left`, а не `right`?

Когда цикл завершается, `left` указывает на первую позицию, где элемент >=
`target` (если такой есть), или на `nums.size` (если все элементы меньше). Это и
есть место вставки.  
`right` в этот момент будет `left - 1`, поэтому возвращаем именно `left`.

---

### Сложность

- **Время:** O(log n)
- **Память:** O(1)

---

### Связь с задачами, которые мы уже разобрали

- Это прямой аналог **нижней границы** (lower_bound).
- Если бы мы искали позицию для вставки *после* последнего вхождения (
  upper_bound), то возвращали бы `right+1` или `left` при другой логике. Но
  здесь нам нужна именно левая граница, поэтому алгоритм идеально подходит.

# Lower Bound

## Задача 35: почему возвращаем `left` после `left > right`?

Ты абсолютно прав, что это сбивает с толку. Давай разберёмся.

Когда мы выходим из цикла `while (left <= right)`, у нас **`left > right`**. В
этот момент:

- `left` — это индекс, **куда нужно вставить `target`**, чтобы массив остался
  отсортированным.
- `right` — это индекс, который на единицу меньше `left` (то есть
  `right = left - 1`).

Это не случайность, а **инвариант классического бинарного поиска для поиска
места вставки**. Давай посмотрим, как меняются `left` и `right` в процессе:

- Если `nums[mid] < target`, то `target` должен быть **правее** `mid`, и мы
  делаем `left = mid + 1`.
- Если `nums[mid] > target`, то `target` должен быть **левее** `mid`, и мы
  делаем `right = mid - 1`.
- Если `nums[mid] == target`, мы сразу возвращаем `mid` (но могли бы и не
  возвращать, а продолжать искать левую границу).

В конце цикла (когда не нашли `target`) `left` всегда указывает на **первый
элемент, который больше `target`** (если такой есть) или на `nums.size` (если
все элементы меньше). Именно это и есть позиция для вставки.

---

### Что такое `lower_bound`?

`lower_bound` — это **стандартный алгоритм** из C++ (и многих других языков),
который возвращает итератор на **первый элемент, не меньший (`>=`) заданного
значения**. Это как раз то, что мы делаем, но с одним отличием: в классическом
бинарном поиске мы останавливаемся при нахождении `target`, а `lower_bound`
продолжает поиск, даже если нашёл, чтобы найти самое левое вхождение.

`lower_bound` — это **отдельный алгоритм**, но его реализация основана на том же
бинарном поиске. Он не ограничивается задачей вставки; он используется для
поиска границ в отсортированных данных, для подсчёта количества элементов в
диапазоне и т.д.

---

### Реализация `lower_bound` на Kotlin

Вот как выглядит чистый `lower_bound` (поиск левой границы):

```kotlin
fun lowerBound(nums: IntArray, target: Int): Int {
    var left = 0
    var right = nums.size // right не включительно
    while (left < right) {
        val mid = left + (right - left) / 2
        if (nums[mid] >= target) {
            right = mid   // ищем левее, включая mid
        } else {
            left = mid + 1
        }
    }
    return left // или right, они равны
}
```

Обрати внимание:

- Мы **не проверяем** `nums[mid] == target` на ранний выход. Мы продолжаем
  сужать интервал, пока `left < right`.
- В конце `left` всегда указывает на первое вхождение `target` (если оно есть)
  или на место вставки (если его нет).

Для задачи 35 мы могли бы использовать этот код, но мы использовали упрощённый
вариант с ранним возвратом, потому что нам не нужно самое левое вхождение — нам
достаточно любого, а если нет, то вернуть позицию вставки. Это экономит одну-две
итерации, но логически то же самое.

---

### Связь между нашей реализацией и `lower_bound`

В нашей реализации мы делаем ранний возврат при `nums[mid] == target`. Если мы
уберём этот ранний возврат и заменим его на `right = mid - 1` (как в
`lower_bound` для поиска левой границы), то в конце мы всё равно получим позицию
вставки, которая будет совпадать с индексом `target`, если он есть. Однако наш
подход короче и понятнее для этой конкретной задачи.

---

### Почему возвращаем `left`, а не `right`?

В момент выхода из цикла `left = right + 1`. Представь массив `[1,3,5,6]`,
`target = 2`:

- После итераций `left = 1`, `right = 0`.  
  Место вставки — индекс `1`. `left` даёт нам правильный ответ. `right` дал бы
  `0`, что неверно.

Если бы мы использовали полуоткрытый интервал `[left, right)` с условием
`while (left < right)`, то по окончании цикла `left == right`, и мы могли бы
вернуть `left` (или `right` — они равны). В нашем коде с замкнутым интервалом
`[left, right]` выход происходит при `left > right`, и правильным является
`left`.

---

### Итог

- `lower_bound` — это **отдельный стандартный алгоритм**, который реализует
  бинарный поиск для нахождения первой позиции, где элемент `>= target`.
- Наша реализация для задачи 35 использует ту же идею, но с ранним выходом при
  совпадении — это частный случай.
- Возврат `left` после выхода из цикла — это стандартный приём, основанный на
  инварианте бинарного поиска: в конце `left` всегда указывает на место вставки.
