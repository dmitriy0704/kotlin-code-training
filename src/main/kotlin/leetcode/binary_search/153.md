# 153. Find Minimum in Rotated Sorted Array

Предположим, массив длиной n, отсортированный в порядке возрастания,
поворачивается от 1 до n раз. Например, массив nums = [0,1,2,4,5,6,7] может
стать следующим:

- [4,5,6,7,0,1,2] если бы его повернули 4 раза.
- [0,1,2,4,5,6,7], если бы его повернули 7 раз.

Обратите внимание, что поворот массива [a[0], a[1], a[2], ..., a[n-1]] 1 раз
приводит к массиву [a[n-1], a[0], a[1], a[2], ..., a[n-2]].

Имея отсортированный повернутый массив nums уникальных элементов, верните
минимальный элемент этого массива.

Вам необходимо написать алгоритм, работающий за время O(log n).

Example 1:
Input: nums = [3,4,5,1,2]
Output: 1
Пояснение: Исходный массив [1,2,3,4,5] был повернут 3 раза.

Example 2:
Input: nums = [4,5,6,7,0,1,2]
Output: 0
Пояснение: Исходный массив имел вид [0,1,2,4,5,6,7] и был повернут 4 раза.

Example 3:
Input: nums = [11,13,15,17]
Output: 11
Пояснение: Исходный массив был [11,13,15,17], и он был повернут 4 раза.

Constraints:

n == nums.length
1 <= n <= 5000
-5000 <= nums[i] <= 5000
All the integers of nums are unique.
nums is sorted and rotated between 1 and n times.

## Решение

## Переходим к задаче 153. Find Minimum in Rotated Sorted Array

Отлично! Ты уже освоил поиск элемента в повёрнутом массиве (задача 33). Теперь
давай разберём **задачу 153**, которая немного проще: нужно найти **минимальный
элемент** в таком же повёрнутом отсортированном массиве (без дубликатов).

### Условие задачи

> Дан массив, который был отсортирован по возрастанию, а затем повёрнут (
> например, `[3,4,5,1,2]`). Все элементы уникальны. Нужно найти минимальный
> элемент за O(log n).

### Идея решения

Минимальный элемент в таком массиве — это **точка разрыва**, т.е. единственное
место, где последовательность убывает (например, в `[3,4,5,1,2]` это переход от
`5` к `1`). Мы можем найти его с помощью бинарного поиска.

Сравниваем средний элемент `nums[mid]` с **правым** крайним `nums[right]`:

- Если `nums[mid] > nums[right]`, то минимальный элемент находится **справа** от
  `mid` (включая `mid+1`), потому что левая часть от `left` до `mid` содержит
  только бóльшие элементы, а минимум — где-то в правой, меньшей части.  
  → `left = mid + 1`

- Иначе (`nums[mid] <= nums[right]`), то правая половина (от `mid` до `right`)
  уже отсортирована по возрастанию, и минимальный элемент находится в левой
  половине (включая `mid`).  
  → `right = mid`

Когда `left == right`, мы нашли минимальный элемент (он находится по этому
индексу).

**Почему это работает?**  
В повёрнутом массиве если `nums[mid] > nums[right]`, то точка разрыва (
минимальный элемент) лежит правее середины. Если же `nums[mid] <= nums[right]`,
то правая часть упорядочена и не содержит минимума (кроме, возможно, самого
`mid`), поэтому минимум слева или равен `mid`.

### Реализация на Kotlin

```kotlin
class Solution {
    fun findMin(nums: IntArray): Int {
        var left = 0
        var right = nums.lastIndex

        while (left < right) {
            val mid = left + (right - left) / 2
            if (nums[mid] > nums[right]) {
                // минимум в правой половине (исключаем mid)
                left = mid + 1
            } else {
                // минимум в левой половине или равен mid
                right = mid
            }
        }
        return nums[left] // или nums[right], они равны
    }
}
```

Обрати внимание: условие цикла `while (left < right)`, а не `<=`, потому что мы
сужаем интервал до одного элемента. В конце `left == right`, и мы возвращаем
значение.

### Пошаговый пример

Возьмём массив `[4, 5, 6, 7, 0, 1, 2]`:

1. `left=0, right=6, mid=3` → `nums[3]=7`, `nums[right]=2`  
   `7 > 2` → минимум справа → `left = 4`

2. `left=4, right=6, mid=5` → `nums[5]=1`, `nums[6]=2`  
   `1 > 2`? Нет (1 <= 2) → минимум слева или на `mid` → `right = 5`

3. `left=4, right=5, mid=4` → `nums[4]=0`, `nums[5]=1`  
   `0 > 1`? Нет → `right = 4`

4. `left=4, right=4` → выход, возвращаем `nums[4] = 0`.

### Почему здесь проще, чем в задаче 33?

- В задаче 33 мы искали конкретное значение `target` и должны были учитывать,
  попадает ли `target` в отсортированную половину. Здесь мы просто ищем минимум,
  поэтому нам достаточно сравнивать `nums[mid]` с `nums[right]` (или
  `nums[left]`) и двигать границы.
- Мы не делаем дополнительных проверок на попадание в диапазон — просто сужаем
  интервал, пока не останется один элемент.

### Ещё один вариант: сравнение с `nums[left]`

Можно также сравнивать `nums[mid]` с `nums[left]`:

- Если `nums[mid] >= nums[left]` → левая часть отсортирована, минимум справа (
  если `mid` не является точкой разрыва) → `left = mid + 1`
- Иначе → минимум слева → `right = mid`

Но сравнение с `nums[right]` проще и надёжнее, потому что не требует отдельной
обработки случая, когда массив не повёрнут (тогда минимум — первый элемент, и
алгоритм с `right` тоже корректно сработает).

### Сложность

- **Время**: O(log n)
- **Память**: O(1)

Хороший вопрос! Давай разберём этот кусок кода максимально детально, потому что
в нём скрыта вся суть алгоритма для поиска минимума в повёрнутом массиве.

Контекст
У нас есть массив, который изначально был отсортирован по возрастанию, а затем
повёрнут (сдвинут) вправо на неизвестное количество позиций. Все элементы
уникальны.

На каждом шаге бинарного поиска мы имеем интервал [left, right] и смотрим на
средний элемент nums[mid] и на крайний правый nums[right].

Ключевое наблюдение
В повёрнутом отсортированном массиве (без дубликатов) есть только одно место,
где порядок нарушается — это «разрыв», после которого идёт минимальный элемент.
Например:

- [3,4,5,1,2] — разрыв между 5 и 1; минимум = 1.

- Если массив не повёрнут (т.е. просто отсортирован), то разрыва нет, и
  минимум — первый элемент.

Теперь рассмотрим любой подмассив [left, right] внутри этого массива. Он тоже
является частью повёрнутого массива, а значит, он либо полностью отсортирован,
либо содержит точку разрыва.

Что говорит условие nums[mid] > nums[right]?

Случай 1: nums[mid] > nums[right]
Это означает, что элемент в середине больше элемента справа. В отсортированном
по возрастанию массиве такого быть не может (если массив не убывает, то
последний элемент должен быть больше или равен среднему). Значит, этот интервал
точно содержит точку разрыва, и она находится где-то справа от mid.
Почему? Потому что если nums[mid] > nums[right], то у нас есть убывание где-то
между mid и right. В повёрнутом массиве это убывание возможно только в одном
месте — в точке разрыва, после которой идёт минимальный элемент. Следовательно,
минимальный элемент лежит в правой половине интервала от mid+1 до right, потому
что сам nums[mid] точно не является минимальным (он больше nums[right], значит,
есть элемент меньше него).
Поэтому мы отбрасываем левую часть вместе с mid: left = mid + 1.

Случай 2: nums[mid] <= nums[right]
Теперь nums[mid] меньше или равен nums[right]. Что это значит?

- Если nums[mid] < nums[right], то от mid до right значения возрастают (или не
  убывают), т.е. правая часть отсортирована и не содержит точки разрыва. Но
  тогда минимальный элемент должен находиться где-то слева от mid (или сам mid
  может быть минимальным).
- Если nums[mid] == nums[right], то это означает, что у нас дубликаты (но в
  задаче 153 их нет, поэтому этот случай не встречается; в 154 — да, но там
  другая логика). Для задачи 153 мы просто рассматриваем строгое >.
  Значит, в этом случае минимальный элемент не может быть правее mid (потому что
  там всё больше или равно nums[mid]). Он либо равен nums[mid], либо находится
  где-то слева. Поэтому мы можем сохранить mid в интервале поиска и отбросить
  правую часть: right = mid.

Почему right = mid, а не right = mid - 1?

Потому что мы не можем исключить сам mid. Возможна ситуация, когда nums[mid] —
это как раз минимальный элемент. Например, в массиве [1,2,3,4,5] (без поворота)
при mid = 2 (nums[2]=3) и right = 4 (nums[4]=5): 3 <= 5 → мы устанавливаем
right = mid = 2. На следующей итерации left=0, right=2, mid=1 (nums[1]=2) → 2 <=
5 → right = 1, затем left=0, right=1, mid=0 → 1 <= 2 → right = 0, и мы выходим,
возвращая nums[0]=1 (минимум). Если бы мы сделали right = mid - 1, то мы бы
потеряли минимум.

Таким образом, right = mid гарантирует, что минимальный элемент всегда остаётся
в интервале [left, right], пока мы не сойдёмся к одной точке.

Почему right = mid, а не right = mid - 1?

Потому что мы не можем исключить сам mid. Возможна ситуация, когда nums[mid] —
это как раз минимальный элемент. Например, в массиве [1,2,3,4,5] (без поворота)
при mid = 2 (nums[2]=3) и right = 4 (nums[4]=5): 3 <= 5 → мы устанавливаем
right = mid = 2. На следующей итерации left=0, right=2, mid=1 (nums[1]=2) → 2 <=
5 → right = 1, затем left=0, right=1, mid=0 → 1 <= 2 → right = 0, и мы выходим,
возвращая nums[0]=1 (минимум). Если бы мы сделали right = mid - 1, то мы бы
потеряли минимум.

Таким образом, right = mid гарантирует, что минимальный элемент всегда остаётся
в интервале [left, right], пока мы не сойдёмся к одной точке.

Итог

- Условие nums[mid] > nums[right] говорит, что минимум справа (исключая mid),
  поэтому left = mid + 1.
- Иначе минимум слева или на mid, поэтому мы сохраняем mid как правую границу:
  right = mid.
- Это стандартный шаблон для поиска минимума в таком массиве.

Контекст: что мы ищем?

Мы ищем минимальный элемент в повёрнутом отсортированном массиве (без
дубликатов). В таком массиве есть одна особенность: все элементы до точки
разрыва больше, чем все элементы после неё. Например:

```text
[4, 5, 6, 7, 0, 1, 2]
       ↑ точка разрыва (минимум = 0)
       
Или если массив не повёрнут (т.е. просто отсортирован), минимум — первый элемент:

[1, 2, 3, 4, 5]

```

Что мы знаем о nums[mid] и nums[right]?

- nums[right] — это последний элемент текущего интервала [left, right].
- nums[mid] — элемент посередине.

Сравнивая их, мы можем определить, где находится точка разрыва (и,
соответственно, минимум).

Случай 1: nums[mid] > nums[right]
Это значит, что последовательность убывает где-то между mid и right. Почему?
Потому что в обычном отсортированном массиве nums[mid] всегда был бы меньше или
равен nums[right]. Если же он больше, то это явный признак того, что точка
разрыва (переход от большого числа к маленькому) находится правее mid.

Пример:
[4, 5, 6, 7, 0, 1, 2], left=0, right=6, mid=3 → nums[3]=7, nums[6]=2 → 7 > 2 →
точка разрыва где-то справа от индекса 3.
Мы можем смело отбросить левую часть, включая mid, потому что все элементы от
left до mid (включая mid) больше минимального элемента, который находится
справа. Поэтому:

```text
left = mid + 1
```

Случай 2: nums[mid] <= nums[right]
Это значит, что правая часть от mid до right отсортирована по возрастанию (или
содержит минимум, который может быть равен nums[mid]).
В этом случае минимальный элемент не может находиться строго правее mid, потому
что если правая часть отсортирована, то её минимальный элемент — это nums[mid] (
или nums[mid+1], но nums[mid] точно меньше или равен всем справа).
Следовательно, минимум находится либо на позиции mid, либо левее.

Пример:
Возьмём тот же массив, но после первого шага: left=4, right=6, mid=5 → nums[5]
=1, nums[6]=2 → 1 <= 2 → правая часть [1,2] отсортирована, минимум = 1 (на mid
или левее).
Мы не можем отбросить mid, потому что это может быть сам минимум. Поэтому мы
сужаем интервал, делая right = mid, сохраняя mid как возможный кандидат.

Почему right = mid, а не right = mid - 1?
Потому что мы ещё не проверили, не является ли nums[mid] минимальным. Если мы
сделаем right = mid - 1, мы можем потерять минимальный элемент, если он оказался
на позиции mid. В бинарном поиске, когда мы ищем минимум (или максимум), мы
часто используем такой приём: если условие выполняется, мы оставляем mid в
интервале, потому что он может быть ответом.

Сравнение с задачей 33 (поиск элемента)
В задаче 33 мы использовали замкнутый интервал [left, right] и условие while (
left <= right). Там мы точно знали, что если target не равен nums[mid], то мы
можем отбросить mid (left = mid + 1 или right = mid - 1), потому что мы уже
проверили этот элемент.
В задаче 153 мы используем полуоткрытый подход: мы не проверяем nums[mid] на
равенство (нам не с чем сравнивать), мы просто сужаем интервал, но всегда
сохраняем mid как возможный минимум, пока не останется один элемент. Поэтому
right = mid, а не mid - 1.

Итог по условиям
nums[mid] > nums[right] → точка разрыва справа → отбрасываем mid и всё, что
слева от него → left = mid + 1.

nums[mid] <= nums[right] → правая часть упорядочена → минимум либо на mid, либо
слева → оставляем mid в интервале → right = mid.

Цикл продолжается, пока left < right, и когда они сравняются, этот единственный
индекс и будет указывать на минимум.

Отличный вопрос! Давай разберём этот код детально, потому что здесь кроется
ключевая логика поиска минимума в повёрнутом массиве. Ты правильно уловил суть:
мы сдвигаем границы в зависимости от того, где находится минимум. Но давай
разберёмся, почему мы сдвигаем именно так и почему в одном случае right = mid, а
не mid - 1.

Что мы знаем о массиве?
Массив nums — это отсортированный по возрастанию массив, который был циклически
сдвинут (повёрнут). Это означает, что у него есть ровно один "разрыв" — место,
где последовательность нарушается (например, переход от максимального элемента к
минимальному). Все элементы уникальны.

Например: [4,5,6,7,0,1,2]

- Разрыв между 7 (индекс 3) и 0 (индекс 4).
- Минимальный элемент — это 0 (первый элемент после разрыва).

Анализ условия nums[mid] > nums[right]
Рассмотрим два возможных случая:

Случай 1: nums[mid] > nums[right]
Это означает, что середина находится слева от разрыва (или разрыв находится
где-то между mid и right). Почему?

- В обычном отсортированном массиве (без поворота) все элементы слева меньше
  элементов справа, поэтому nums[mid] всегда меньше nums[right].
- Если nums[mid] > nums[right], значит, где-то справа от mid есть падение (
  разрыв), и минимальный элемент находится в правой части.
- Пример: [4,5,6,7,0,1,2], mid=3 (nums[3]=7), right=6 (nums[6]=2). 7 > 2 →
  разрыв справа, минимум 0 находится правее mid.

В этом случае мы уверены, что минимальный элемент не может находиться в левой
половине (включая mid), потому что левая половина — это отсортированный
возрастающий участок, и все его элементы больше nums[mid], а nums[mid] уже
больше nums[right], значит, минимум точно справа. Поэтому мы отбрасываем левую
половину вместе с mid: left = mid + 1.

Случай 2: nums[mid] <= nums[right]
Это означает, что середина находится справа от разрыва (или разрыва вообще нет,
т.е. массив не повёрнут). Почему?

- Если nums[mid] <= nums[right], то правая часть (от mid до right) является
  непрерывно возрастающей (или уже содержит минимум в самом mid). То есть
  разрыв (если он есть) находится левее mid или в самой точке mid.

- Пример: [4,5,6,7,0,1,2], mid=5 (nums[5]=1), right=6 (nums[6]=2). 1 <= 2 →
  правая часть [1,2] возрастает, разрыв левее, минимум 0 находится левее mid (
  или может быть равен mid? Нет, здесь mid не минимум, но в общем случае минимум
  может быть равен mid, если mid — первый элемент после разрыва, например, если
  mid=4, nums[4]=0).

Теперь важный момент: куда двигать правую границу?
Мы знаем, что минимальный элемент находится либо левее mid, либо в самом mid.
Почему не может быть правее? Потому что правая часть от mid до right возрастает,
и nums[mid] — это её минимальный элемент (так как она возрастает).
Следовательно, если минимум и существует в правой части, то это и есть
nums[mid]. Но если минимум меньше nums[mid], то он должен быть левее. Поэтому мы
можем безопасно установить right = mid, исключая все элементы правее mid, но
оставляя mid в интервале поиска, потому что mid может быть искомым минимумом.

Почему right = mid, а не mid - 1?

- Если бы мы сделали right = mid - 1, мы бы исключили mid из рассмотрения. Но
  mid может быть минимальным элементом (например, в массиве [1,2,3] — не
  повёрнут, минимум 1 на индексе 0, но допустим, что mid оказался минимумом в
  какой-то итерации). Если мы исключим mid, мы можем потерять ответ.
- Поэтому мы оставляем mid в интервале, устанавливая right = mid. Это
  гарантирует, что если mid и есть минимум, мы его не потеряем.

Сравнение с обычным бинарным поиском

В обычном бинарном поиске, когда мы ищем точное значение, мы всегда исключаем
mid (делаем left = mid + 1 или right = mid - 1), потому что мы уже проверили mid
и он не равен target. Здесь же мы не проверяем mid на равенство чему-то, мы
просто сужаем интервал, и mid может быть ответом. Поэтому мы не исключаем его
полностью — только в случае nums[mid] > nums[right] мы уверены, что mid точно не
минимум, и можем исключить его (и всё левое), но в обратном случае мы не можем
исключить mid, поэтому оставляем его.

Итог
Если nums[mid] > nums[right] → разрыв справа → минимум правее mid → left = mid +

1.

Если nums[mid] <= nums[right] → правая часть возрастает → минимум либо левее
mid, либо в самом mid → right = mid.

Этот подход работает, потому что на каждом шаге мы отбрасываем половину
элементов, но при этом всегда сохраняем возможность, что mid — минимальный
элемент. В конце, когда left == right, мы получаем индекс минимума.

Мы с тобой разбираем задачу 153. Ты запутался в логике, когда nums[mid] <=
nums[right]. Давай я попробую объяснить максимально наглядно, без абстракций.

Суть: мы ищем минимум в повёрнутом отсортированном массиве. Минимум — это точка,
где массив "ломается": например, [4,5,6,7,0,1,2] — минимум = 0.

Что мы знаем о массиве? Он состоит из двух возрастающих частей: первая часть (
например, 4,5,6,7) и вторая (0,1,2). Минимум — это первый элемент второй части.

Теперь смотрим на mid и right:

- Если nums[mid] > nums[right], то это означает, что mid находится в первой (
  большей) части, а right — во второй (меньшей). Это возможно только если точка
  разрыва (минимум) находится где-то между mid+1 и right. Поэтому мы отбрасываем
  левую часть (включая mid) и двигаем left = mid + 1.

- Если nums[mid] <= nums[right], то mid и right находятся в одной и той же
  возрастающей части. Это может быть либо вторая часть (если обе позиции после
  разрыва), либо первая (если массив вообще не повёрнут и весь отсортирован). В
  любом случае, правая часть от mid до right является возрастающей (или не
  убывающей). Значит, минимальный элемент в этой правой части не может быть
  правее mid, потому что nums[mid] уже меньше или равен nums[right], и все
  элементы между ними больше или равны nums[mid]. Следовательно, минимум
  находится либо в левой половине (включая mid), либо это сам mid. Поэтому мы
  отбрасываем правую часть (все элементы после mid) и делаем right = mid.

Главное, что ты должен осознать: мы не просто "двигаем границу влево", мы
исключаем ту часть массива, которая гарантированно не содержит минимума. Если
nums[mid] <= nums[right], то мы знаем, что все элементы от mid до right идут по
возрастанию, и nums[mid] — самый маленький в этом отрезке. Поэтому минимум всего
массива не может быть правее mid (потому что там все больше или равны
nums[mid]). Значит, мы смещаем right на mid, чтобы проверить левую часть и сам
mid.

одна: если правая часть (от mid до right) возрастает, то минимум не справа, а
слева или в mid. Поэтому мы отбрасываем правую часть. Это не "одно и то же", это
разные условия.
