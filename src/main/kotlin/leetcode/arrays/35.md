# 35. Search Insert Position

## Условие

Имея отсортированный массив различных целых чисел и целевое значение, верните
индекс, если целевое значение найдено. В противном случае верните индекс, по
которому оно находилось бы, если бы было вставлено в порядке возрастания.

Вам необходимо написать алгоритм со сложностью выполнения O(log n).

Example 1:

Input: nums = [1,3,5,6], target = 5
Output: 2

Example 2:

Input: nums = [1,3,5,6], target = 2
Output: 1

Example 3:

Input: nums = [1,3,5,6], target = 7
Output: 4

Constraints:

1 <= nums.length <= 10^4
-10^4 <= nums[i] <= 10^4
nums contains distinct values sorted in ascending order.
-10^4 <= target <= 10^4

## Решение

## Решение задачи 35. Search Insert Position на Kotlin

**Задача:**  
Дан **отсортированный** массив целых чисел `nums` (без дубликатов) и целое число
`target`.  
Нужно вернуть индекс, по которому находится `target`, если он есть. Если
`target` отсутствует, вернуть индекс, на который его следует вставить, чтобы
сохранить порядок сортировки.

**Примеры:**

- `nums = [1,3,5,6], target = 5` → возвращаем `2` (индекс 5).
- `nums = [1,3,5,6], target = 2` → возвращаем `1` (вставка между 1 и 3).
- `nums = [1,3,5,6], target = 7` → возвращаем `4` (в конец).
- `nums = [1,3,5,6], target = 0` → возвращаем `0` (в начало).

---

### Оптимальное решение – бинарный поиск (O(log n))

Так как массив отсортирован, бинарный поиск идеально подходит.

**Алгоритм:**

1. Устанавливаем левую границу `left = 0`, правую `right = nums.size - 1`.
2. Пока `left <= right`:
    - Находим середину `mid = left + (right - left) / 2`.
    - Если `nums[mid] == target` → возвращаем `mid`.
    - Если `nums[mid] < target` → ищем в правой половине: `left = mid + 1`.
    - Иначе → `right = mid - 1`.
3. После цикла `left` указывает на позицию, куда следует вставить `target`.
   Возвращаем `left`.

**Почему `left`?**  
Если цель не найдена, то после выхода из цикла `left` всегда будет индексом
первого элемента, большего `target`. Это и есть позиция вставки. Например, для
`[1,3,5,6]` и `target = 2`:

- `left` станет 1, что верно.

---

### Код на Kotlin

```kotlin
class Solution {
    fun searchInsert(nums: IntArray, target: Int): Int {
        var left = 0
        var right = nums.size - 1

        while (left <= right) {
            val mid = left + (right - left) / 2
            when {
                nums[mid] == target -> return mid
                nums[mid] < target -> left = mid + 1
                else -> right = mid - 1
            }
        }
        return left
    }
}
```

**Примечания:**

- Используем `when` для наглядности. Можно написать с `if-else`.
- Вычисление `mid` через `left + (right - left) / 2` избегает переполнения при
  больших `left` и `right`.
- Цикл завершается, когда `left > right`. В этот момент `left` — искомая
  позиция.

---

### Сложность

- **Время:** O(log n) — стандартный бинарный поиск.
- **Память:** O(1) — используем только несколько переменных.

---

### Альтернатива – линейный поиск (O(n))

Если вы только начинаете, можно и просто пройтись по массиву:

```kotlin
fun searchInsert(nums: IntArray, target: Int): Int {
    for (i in nums.indices) {
        if (nums[i] >= target) return i
    }
    return nums.size
}
```

Но бинарный поиск эффективнее и ожидается на собеседованиях.

## Разбор: почему `left` даёт позицию вставки

В бинарном поиске мы поддерживаем **инвариант**:

- **Все элементы с индексом < `left`** **меньше** `target`.
- **Все элементы с индексом > `right`** **больше** `target`.

Когда цикл завершается (`left > right`), ни один элемент не может находиться
между `left` и `right`, потому что они пересеклись. В этот момент:

- `left` указывает на **первый индекс**, где элемент **>= target** (если такой
  есть), или на `nums.size` (если все элементы меньше `target`).
- Это и есть позиция для вставки, чтобы сохранить порядок.

---

### Пример: `nums = [1, 3, 5, 6]`, `target = 2`

1. **Начало:** `left = 0`, `right = 3`.
2. **Шаг 1:** `mid = (0+3)/2 = 1` → `nums[1] = 3`.
    - `3 > 2` → значит, `target` должен находиться левее.
    - Сдвигаем `right = mid - 1 = 0`.
3. **Шаг 2:** `left = 0`, `right = 0`.
    - `mid = 0` → `nums[0] = 1`.
    - `1 < 2` → значит, `target` должен находиться правее.
    - Сдвигаем `left = mid + 1 = 1`.
4. **Цикл завершается**, так как `left = 1`, `right = 0` → `left > right`.
5. **Результат:** `left = 1`.
    - Проверяем: массив `[1, 3, 5, 6]`, вставка `2` должна быть на позиции 1 (
      перед `3`). Всё верно.

---

### Другие примеры для наглядности

- **`target = 4`**:
    - `left=0,right=3` → mid=1 (3<4) → left=2.
    - `left=2,right=3` → mid=2 (5>4) → right=1.
    - `left=2,right=1` → выход, `left=2`. Вставка после `3` перед `5` — позиция
      2.

- **`target = 0`**:
    - `left=0,right=3` → mid=1 (3>0) → right=0.
    - `left=0,right=0` → mid=0 (1>0) → right=-1.
    - `left=0,right=-1` → выход, `left=0`. Вставка в начало.

- **`target = 7`**:
    - `left=0,right=3` → mid=1 (3<7) → left=2.
    - `left=2,right=3` → mid=2 (5<7) → left=3.
    - `left=3,right=3` → mid=3 (6<7) → left=4.
    - `left=4,right=3` → выход, `left=4` (= `nums.size`) — вставка в конец.

---

### Почему именно `left`, а не `right`?

После завершения цикла `right = left - 1`. Если бы мы вернули `right`, получили
бы индекс последнего элемента **меньшего** `target`, а нужен первый **больший**
или равный. Поэтому возвращаем `left`.

Всё просто и логично. Теперь это свойство бинарного поиска должно быть понятно.
